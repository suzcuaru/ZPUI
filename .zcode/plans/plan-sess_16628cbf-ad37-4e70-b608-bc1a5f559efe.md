## Переработка проверки/подбора стратегий — план

Диагностика (через 2 Explore-агента) подтвердила корни багов:

**Баг 1 (ПКМ-проверка: спам, «туда-сюда», не завершается):**
- `SingleStrategyTestModal`: `onDone` — инлайн-функция (новая на каждом рендере), а StrategiesTab перерисовывается каждые 2 сек (polling статуса) → эффект модалки перезапускается → POST теста отправляется заново каждые ~2 сек → тест рестартует бесконечно; poll-цепочки множатся.
- Бэкенд: во время пересоздания службы (SetStrategy) health-монитор видит «движок упал» и каждые 5 сек запускает recovery, который переустанавливает службу → конфликт с тестом («туда-сюда»). ISP-монитор тоже может вмешаться.
- Дублирующий слушатель `strategy:single_test` в ZapretPage + персистентные error-тосты = спам.

**Баг 2 (автоподбор «висит», отмена не работает):**
- Фронт: список результатов рисуется только после завершения; события теряются (`EventsOff` в close() стрима снимает слушателей у StartupScreen/модалки одновременно, и тот же close() дёргает `CancelAutoTest` — чужой забег убивается); `JSON.parse` без try/catch — одно кривое событие навсегда оставляет `running=true`.
- Отмена: бэкенд после отмены уходит в `applyBest` и **применяет лучшую из протестированных** вместо остановки; goroutine `SetStrategy` не прерывается (держит `applyMu` до ~100 сек) — выглядит как зависание.

### Правки бэкенда

1. **`internal/zapret/single_check.go`** — контекст и отмена: `testCtx` с cancel, регистрация отмены в Manager (как autoTestCancel); sleep и BulkCheck уважают ctx (таймаут 60с); сохранение в БД — `UpdateStrategyAvailability` + `SaveOperatorStrategy` (одна стратегия, свой JSON) — данные только по ней; restore исходной остаётся.
2. **`internal/zapret/strategy.go` (AutoSelectAndApply)** — при отмене (`testCtx.Done()` в `applyBest`) восстанавливать исходную стратегию вместо «применить лучшую из проверенных»; частичное сохранение в БД по ходу цикла уже добавлено — остаётся.
3. **`internal/app/app.go`** (гварды, не зона обновлений): health-монитор и ISP-монитор перед вмешательством проверяют `IsAutoTestRunning()` — не дёргают recovery/SetStrategy во время теста.
4. **Событие `strategy:changed`** — во время single-теста помечать payload (`source: "single_test"`), фронт не тостит такие переключения.
5. **Логи 7 дней**: `CleanOld`/очистка — 30 дней → 7 дней (лог-файлы и logs.db).

### Правки фронтенда

6. **`SingleStrategyTestModal.jsx` — полная переработка**: запуск строго один раз (ref-гварды, `onDone` в useRef); одна poll-цепочка с alive-флагом; кнопка «Отменить» во время теста (POST `/api/strategy/cancel` + закрытие); этапы «Применяем стратегию… → Проверяем ресурсы… → результат (N/M, %)»; итоговый экран: успех/слабая/ошибка + «данные обновлены в базе».
7. **`AutoSelectModal.jsx` — полная переработка UX**: live-список стратегий во время работы (✓ проверена +%/ошибка/текущая со спиннером/ожидает), крупный счётчик N/M + прогресс-бар + текущая стратегия + ETA; `JSON.parse` в try/catch; «Отменить» — останавливает и **возвращает исходную стратегию** (по пункту 2 бэка), с экраном «Подбор отменён»; по завершении — бейдж применённой стратегии (из события `result.strategy`, без парсинга русских строк).
8. **`api.js` (createStream)**: `close(cancel=false)` — `CancelAutoTest` вызывается только при отмене (не после успешного done/не при закрытии чужих стримов); matчинг веток уже по `base` — остаётся.
9. **`App.jsx`/`StartupScreen`**: совместимость с новой схемой (стрим больше не убивает чужие забеги при закрытии).
