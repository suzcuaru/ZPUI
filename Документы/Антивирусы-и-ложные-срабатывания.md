# Антивирусы, SmartScreen и ZPUI — план работы без сертификата подписи

> Статус: рабочий план. Дата: 29.10.2026. Обновлять при изменении ситуации.
> Контекст: ZPUI — проприетарное Go-приложение (Wails v2) + кастомные
> Go-инсталляторы/обновлятор. Код-сертификат подписи недоступен (санкционные
> ограничения для РФ-разработчика; Azure Trusted Signing — только US/CA;
> SignPath — только open-source). Работаем по трём направлениям: гигиена
> сборки, разбор ложных срабатываний у вендоров, инструкции пользователям.

---

## 1. Почему нас ругают (диагноз)

Профиль ZPUI для эвристик AV — «подозрительный», причём по нескольким
независимым линиям:

1. **Go-бинарник без подписи.** Статический exe с плотным `.text`, высоким
   энтропийным профилем и атипичным импортом — так выглядит значительная
   часть Go-малвари, и ML-эвристики вендоров (Defender Wacatac, Malwarebytes
   Machine Learning и пр.) массово ловят и легитимные Go-программы.
2. **Поведение установщика/обновлятора.** ZPUI-Setup/ZPUI-Update делают
   ровно то, что делает дроппер: убивают процессы по имени
   (`taskkill /IM` по ZPUI.exe, winws2.exe/winws.exe, ZPUI-TgProxy.exe),
   распаковывают вложенный
   payload на диск, заменяют файлы, перезапускаются, управляют службой.
3. **Соседство с движком запрета.** winws2.exe + драйвер WinDivert —
   перехват пакетов на уровне ядра; этот тандем детектят почти все AV
   независимо от нас (у апстрима zapret2 та же история).
4. **Историческая безликость PE.** До 2.0.7 у главного ZPUI.exe вообще не
   было VERSIONINFO-ресурса (пустые поля в свойствах файла) — классический
   триггер; у инсталляторов не было OriginalFilename.

## 2. Что уже сделано в сборке (29.10.2026)

Все пункты — в `build.bat`, проверки — по свойствам собранных exe:

- **VERSIONINFO у ZPUI.exe** — раньше exe собирался «безликим»: Wails-CLI
  генерировал ресурс через winres, и хотя строки в ресурсе были, Windows
  (.NET/Explorer-читалки, которыми пользуются и AV) не показывали их;
  с ключом lang=0x0409 строки читал только «сырой» VerQueryValue, но не
  FileVersionInfo/Проводник. При попытке подложить свой syso рядом wails
  падал («too many .rsrc sections» — два ресурсных файла).
  **Решение:** Wails собирается с флагом `-nopackage` (не генерирует
  свой `ZPUI-res.syso` вообще), а иконка + манифест
  (`installer/app-manifest.xml`, asInvoker + supportedOS Win10/11) +
  полный VERSIONINFO вкладываются goversioninfo — тем же генератором и в
  том же формате, что у Setup/Update, который корректно читается всеми
  читалками. Результат: FileDescription / CompanyName / FileVersion /
  OriginalFilename у ZPUI.exe, Setup, Update, Service заполнены
  (проверено `FileVersionInfo` после сборки).
- **OriginalFilename** добавлен во все versioninfo.json — первое, что
  спрашивают аналитики AV при разборе.
- `LegalCopyright` у модулей приведён к единому виду (был «MIT License»
  при проприетарной EULA).
- Уже было и сохранено: `-ldflags "-s -w -H windowsgui"` + `-trimpath`
  везде, никаких UPX/упаковщиков, никаких обфускаторов (garble и т.п.),
  манифест админа (`requireAdministrator`) у инсталляторов.
- Проверено и осознанно оставлено: `taskkill /IM` строго по двум именам
  нашего ПО (легитимные инсталляторы делают так же; фильтрация по пути
  через taskkill невозможна, PowerShell-вариант сложнее и не стоит того).

Правило на будущее: **не добавлять** в сборку UPX, обфускацию, рандомные
имена временных файлов, динамическую генерацию кода — всё это
конвертирует «возможное ложное срабатывание» в «стабильный детект».

Ещё правило: **не пересобирать релиз без смены версии** — репутация
SmartScreen и вендоров копится на идентичный хеш файла.

**Ловушка для будущих сборок:** не убирать `-nopackage` у `wails build`
в STEP 4 — без него wails генерирует свой syso, конфликтует с нашим
(два `.rsrc` → сборка падает), а его собственный VERSIONINFO формат
winres читается некорректно читалками Windows (пустые поля в свойствах
файла). Наш syso генерируется из `versioninfo.json` в корне на время
сборки и удаляется после — как у инсталляторов.

## 3. Разбор ложных срабатываний у вендоров (бесплатно, без сертификата)

Порядок работы при каждом релизе и по мере поступления жалоб:

1. Собрать детекты: у пользователей спросить **имя антивируса и текст
   детекта** (или скриншот). По хешу смотреть отчёт на
   [virustotal.com](https://www.virustotal.com) **поиском по SHA256, без
   заливки файла** — заливка распространяет билд среди всех вендоров
   (для проприетарного ПО не рекомендуется; VT Trusted Source закрыт).
2. Отправить файл напрямую в формы вендоров, которые детектят. Все формы
   бесплатны, файл в каждом случае — тот же релизный exe (Setup/Update —
   в первую очередь, они скачиваются чаще).
3. В заявке указывать: назначение ПО, сайт, что это не малварь, контактный
   email. Для повторных релизов ссылаться на прежний разбор.

(Microsoft). Результат действует на конкретный хеш — после пересборки
(новой версии) заявки повторять, пока вендор не начнёт относить файлы по
признакам продукта, а не по хешу.

### SmartScreen отдельно

- Официального вайтлиста SmartScreen без подписи не существует; канал тот
  же (filesubmission → SmartScreen).
- Репутация набирается **органически: один и тот же хеш, скачиваемый
  многими пользователями с одного сайта**. Отсюда практика: не менять
  хеш релизных файлов без смены версии, раздавать строго с
  zpui-life.ru/Яндекс.Диска (один источник), не переименовывать файлы.
- Подпись EV с 2024 больше не даёт мгновенной репутации — даже платный
  путь не мгновенный, что снижает цену ожидания.
- Пользовательский обход остаётся прежним: «Подробнее → Выполнить в
  любом случае» (уже описано в FAQ приложения).

## 4. Инструкции для пользователей (если AV всё же ругается)

Коротко, для FAQ/поддержки (без глубокой техники):

1. **SmartScreen при первом запуске**: «Подробнее» → «Выполнить в любом
   случае». Это предупреждение о неизвестном издателе, не вирус.
2. **Антивирус нашёл угрозу в ZPUI/установщике**: проверить имя детекта;
   если файл скачан с zpui-life.ru — это ложное срабатывание; добавить
   файл в исключения (пути: папка установки, установщик) и отправить нам
   название антивируса + текст детекта — отправим разбор вендору.
3. **Ругань на winws2.exe/WinDivert** — это движок запрета, его детектят
   почти все AV у всех подобных программ; исключение на папку zapret
   решает.
4. Не скачивать установщики со сторонних сайтов: файлы вне
   zpui-life.ru/проверенных зеркал не гарантируются.

## 5. Что не решается без сертификата (честный список)

- Зелёная репутация «неизвестного издателя» в SmartScreen для НОВОГО хеша
  (первые дни после релиза) — только ожидание накопления репутации.
- Агрессивные эвристики отдельных AV (например, ML-детекты Malwarebytes)
  на Go-бинарники — снижается гигиеной и разборами, но не до нуля.
- Ругань на WinDivert/winws — вне нашего контроля (сторонний движок).

Если когда-нибудь появится возможность оплаты (не санкционные
ограничения, а именно вопрос платежа): самый дешёвый легальный путь —
обычный OV-сертификат (не EV) у европейского ЦС через посредника,
принимающего оплату из РФ; он убирает «неизвестный издатель» и ускоряет
доверие вендоров, но мгновенного bypassа SmartScreen (как раньше EV) не
даёт — с 2024 это отменили для всех.

## 6. Чек-лист на релиз (добавить в zpui-release)

1. Собрать build.bat; проверить свойства exe: версия/описание/компания/
   OriginalFilename заполнены у ZPUI.exe, Setup, Update, Service.
2. Собрать SHA256 всех файлов (checksums.sha256 уже пишет build.bat).
3. Прогнать поиск по хешам на VT (без заливки) для Setup/Update/ZPUI.exe.
4. По каждому новому детекту — заявка вендору из таблицы §3.
5. Повторить заявки для детектов, известных с прошлых релизов (хеш сменился).
