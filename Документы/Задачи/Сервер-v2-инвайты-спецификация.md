# Сервер ZPUI v2 — спецификация (инвайт-модель)

> Статус: утверждено пользователем 16.09.2026. Заменяет прежнюю реализацию `server/` целиком.
> Модель идентификации: **инвайт-коды** (без email/пароля/нодов). Нода (xray/agent) удалена.

## 1. Модель

- **Аккаунт** создаётся вводом инвайт-кода: пользователь один раз задаёт
  **логин и пароль** (логин уникален, пароль ≥ 6 символов, bcrypt). Вход по
  логину+паролю с любого устройства — это и есть восстановление доступа.
- **Профиль — опционально**: `display_name` и примечание; может быть заполнен
  когда угодно, не влияет на работу.
- **Инвайт** — одноразовый код, который генерирует админ. Несёт тариф:
  `devices_limit` (1/3/5), `duration_days`. Продление подписки = ввод нового
  инвайта в существующий аккаунт (суммирует дни, может поднять devices_limit).
- **Инвайт** — одноразовый код, который генерирует админ. Несёт тариф:
  `devices_limit` (1/3/5), `duration_days`. Продление подписки = ввод нового инвайта
  в существующий аккаунт (суммирует дни, может поднять devices_limit до max).
- **Аккаунт** имеет `expires_at` (подписка). `recovery_code` НЕ используется —
  восстановление = вход по логину+паролю.
- **Устройство**: привязано к аккаунту, лимит `devices_limit`. Авто-регистрация
  анонимного устройства (без аккаунта) сохранена — для телеметрии/баннеров/обновлений.
- **Оплата**: ручная. Админ после получения платежа выдаёт инвайт. Таблицы
  payments/promo — НЕ переносим (заменены инвайтами).
- **Ноды/VPS/xray**: удалены из v2. Сервер — CRM: аккаунты, обновления, баннеры,
  sync, телеметрия. Никаких конфигов VPN в API.

## 2. Стек и структура

```
server/

│   ├── docker-compose.yml / Dockerfile   (порт 8080 внутр., наружу 4430→8080)

│       ├── store.go                      (SQLite modernc, WAL; схема+миграции)
│       ├── store_*.go                    (SQL-методы по доменам)
│       ├── account.go                    (создание/recovery/extend/heartbeat)
│       ├── devices.go                    (авто-регистрация, список, отвязка)
│       ├── updates.go                    (zpui/zapret/components)
│       ├── banners.go, sync.go, telemetry.go
│       ├── admin.go                      (/admin/api/*)
│       └── adminweb/ → собирается в web/admin (base /admin/)
└── backup/                               (dump SQLite — без изменений)
```

Удалить: `server/node/`, `server/mail/`, `server/deploy/` (переписать под новый
состав), `control/api/web/index.html`, `web/lk.html`, старый `adminweb/`, старые
`.exe` из репо.

**Ответы API** (как в клиенте ZPUI): успех `{"status":"ok", ...}`, ошибка
`{"error":"<код>"}` + корректный HTTP-код. Ошибки — строковые коды
(`bad_invite`, `invite_used`, `device_limit`, `not_found`, `unauthorized`…).

## 3. Клиентский API (`/api/v1/*`, Bearer-токен сессии 30 дней)

| Метод/путь | Тело | Ответ/поведение |
|---|---|---|
| POST `/api/v1/account/create` | `{invite_code, login, password, device_id, device_name, display_name?}` | login 3–32 [a-z0-9_], password ≥6, bcrypt; создаёт аккаунт+привязывает устройство; `{token, account_id, devices_limit, expires_at}` |
| POST `/api/v1/account/login` | `{login, password, device_id, device_name}` | вход с любого устройства (bcrypt, rate-limit 5/мин на login); тот же ответ; при превышении devices_limit — `device_limit` |
| POST `/api/v1/account/extend` | (auth) `{invite_code}` | продление: `expires_at = max(now, expires_at) + duration_days`; `devices_limit = max(old, invite)`; повторно код гасится |
| GET `/api/v1/account` | (auth) | состояние: `login, display_name, expires_at, devices_limit, devices[]` |
| POST `/api/v1/account/profile` | (auth) `{display_name?}` | обновление опционального профиля |
| POST `/api/v1/heartbeat` | `{device_id}` | touch устройства; `{expires_at, server_time}` (auth по сессии устройства) |
| POST `/api/v1/device/register` | `{device_id, device_name, app_version}` | анонимное устройство (без аккаунта) — баннеры/обновления/телеметрия |
| GET `/api/v1/device` | (auth) | список устройств аккаунта |
| POST `/api/v1/device/unbind` | (auth) `{device_id}` | отвязка (нельзя отвязать текущее, если аккаунт активен — лимит-защита не нужна: allowed) |
| GET `/api/v1/updates/zpui?device_id=&version=` | | манифест `{version, notes, sha256, force, is_test, url}`; is_test — только устройство-тестер |
| GET `/api/v1/updates/zapret?device_id=&version=` | | аналогично |
| GET `/api/v1/updates/components?device_id=&name=&version=` | | report/xray-подобные компоненты |
| GET `/api/v1/updates/…/download?id=` | | стрим файла |
| GET `/api/v1/banners?device_id=` | | активные (30 дней) минус dismissed |
| POST `/api/v1/banners/dismiss` | `{device_id, banner_id}` | |
| GET/POST `/api/v1/sync/user` | (auth) `{key, data, updated_at}` | KV аккаунта, last-write-wins |
| POST `/api/v1/telemetry` | `{device_id, metrics…}` | анонимно/по сессии |
| POST `/api/v1/telemetry/report` | multipart/markdown ≤4 МБ | отчёт, просмотр в админке |

Auth: `Authorization: Bearer <token>`; токен = случайный 32 байта (hex), в БД
`sessions(token, account_id, device_id, expires_at)`. Анонимные устройства —
без токена, идентификация по `device_id`.

## 4. Админ-API (`/admin/api/*`)

Gate: loopback/RFC1918/100.64/10 + `X-Admin-Token` (из env `ADMIN_TOKEN`, без
дефолта; в DEMO_MODE — `demo-token`). Ответы списков: `{"data":[…]}`.

| Группа | Эндпоинты |
|---|---|
| Обзор | `GET overview` — счётчики: аккаунты/активные подписки/устройства/онлайн 24ч/телеметрия |
| Инвайты | `GET invites?status=`, `POST invites` `{duration_days, devices_limit, count, note}` (batch), `POST invites/revoke {id}` |
| Аккаунты | `GET accounts?q=`, `GET accounts/{id}` (устройства, сессии, extend-история), `POST accounts/{id}/revoke-sessions`, `POST accounts/{id}/tester`, `POST accounts/{id}/reset-password {password}` (сброс пароля админом) |
| Устройства | `GET devices?q=`, `POST devices/{id}/tester`, `DELETE devices/{id}` |
| Обновления | `zpui/zapret/components`: `GET list`, `POST publish` (файл+метаданные, sha256), `POST flags {id, force, is_test, notes}`, `POST delete {id}`, `PUT settings {rollback_to}` |
| Баннеры | CRUD + `GET dismiss-stats` |
| Телеметрия | `GET telemetry?device_id=&limit=`, `GET reports`, `GET reports/{id}`, `GET reports/{id}/raw` |
| События | `GET events?limit=` (журнал: активации, входы, продления, сбои входа) |
| Настройки | `GET/PUT settings` (telemetry_interval_min, min_app_version, banner о servicing) |

## 5. Схема SQLite (v2)

```
accounts(id, login UNIQUE, password_hash, display_name, devices_limit,
         expires_at, is_tester, created_at, updated_at)
invites(id, code UNIQUE, duration_days, devices_limit, note,
        status[unused|used|revoked], used_by→accounts, used_at, created_at)
devices(id, device_id UNIQUE, account_id NULL, name, app_version, is_tester,
        last_seen, created_at)
sessions(token PK, account_id, device_id, expires_at, created_at)
app_updates / zapret_updates / components  (как в v1: версия, файл, sha256,
        notes, force, is_test, created_at, enabled)
banners(id, title_ru, title_en, body_ru, body_en, kind, active_from, active_to, created_at)
banner_dismiss(banner_id, device_id)
user_data(account_id, key, data, updated_at; PK(account_id,key))
telemetry(id, device_id, payload, created_at)
reports(id, device_id, body, created_at)
events(id, kind, subject, details, created_at)
settings(key PK, value)
```

## 6. Админка (adminweb v2)

React 18 + Vite, **дизайн-система ZPUI**: токены из `web/src/styles/` +
[`Документы/Дизайн-и-типографика.md`](../Дизайн-и-типографика.md), референс
компонентов — `mockups/app-ui` (живой стенд) и `web/src/components/ui/`.
Тёмная тема по умолчанию, без роутера (таб-навигация как в ZPUI), локали ru/en
(минимум: подписи разделов). Разделы: Обзор, Инвайты, Аккаунты, Устройства,
Обновления, Баннеры, Телеметрия, Отчёты, События, Настройки.
`vite build` → `control/api/web/admin` (base `/admin/`), отдача http.FileServer.
Токен админа вводится на экране входа, хранится в localStorage (`zpui-admin-token`).

## 7. DEMO_MODE

`DEMO_MODE=1`: `demo-token` для админа; сид-данные (пара аккаунтов, инвайты,
устройства, события) при первом старте на пустой БД. Больше ничего.

## 8. Вне скоупа v2

Ноды/xray/агент, платежи, промокоды, email/SMTP, веб-ЛК (lk.html), синхронизация
сервер-нода, VPN-конфиги. Клиент ZPUI (AuthGate и вызовы) правится отдельной
задачей под этот контракт.
