# Источники обновлений (Авто/ZPUI Live/Яндекс/GitHub/Гитхаб-прокси) + поддержка zapret2

## Проблема

Клиент жёстко зашивает каналы: ZPUI — сервер → Яндекс-фолбэк (`app_server_updates.go:49`,
`app_api_updates.go:84`), zapret — только сервер (`internal/zapret/updater.go:34`, GitHub-ветки
снесены). Юзер не может выбрать источник, а zapret2 клиентом не поддерживается вовсе, хотя
сервер уже раздаёт манифест `/updates/zapret2` (`ZPUI-Server/core/zapret2sync.go:371`).

Факт (важно): апстрим bol-van/zapret2 публикует только Linux-тарболы и zip исходников —
Windows-сборки в релизах нет. Windows-движок zapret2 (winws2.exe) существует в community-бандле
zapret-win-bundle (локальные копии: `../ZPUI/zapret2-study/`). Наработка движковой интеграции —
в экспериментальной ветке `../zpui_2_test` (`internal/zapret/engine.go`: детект `bin/winws2.exe`,
запуск winws2-стратегий; `app_zapret2.go`).

## Цель

Юзер в панели «Обновления» выбирает источник (Авто / ZPUI Live / Яндекс Диск / GitHub /
Гитхаб-прокси); из выбранного источника тянутся и обновления приложения, и запреты
(zapret 1 и 2). В авто-режиме приоритет — ZPUI Live. Появляется поддержка zapret2
(объём — по решению владельца, см. развилку).

## Требования

- R1. Селектор источника в панели «Обновления» (SettingsPage, над строками ZPUI/ZAPRET):
  Авто · ZPUI Live · Яндекс Диск · GitHub · Гитхаб-прокси. Один на оба обновления
  (решение владельца: «из источника тянем и обновление приложения и запретов»).
- R2. Выбор хранится в config.json (`updates_source`), переживает перезапуск, дефолт «auto».
- R3. Авто-приоритет: ZPUI Live → (для ZPUI: Яндекс; для zapret: Яндекс → GitHub → прокси).
  Недоступность источника = тихий переход к следующему (как текущий фолбэк).
- R4. Источники по продуктам:
  - ZPUI: сервер (манифест `/api/v1/updates/zpui`, SHA из манифеста) · Яндекс
    (`checksums.sha256`) · GitHub — релизы `suzcuaru/ZPUI` (в release.yml добавляется
    ассет checksums.sha256; сверка по нему) · Гитхаб-прокси = те же URL через зеркало
    `gh-proxy.com` / `ghfast.top` (те же хосты, что использует сервер: zapretsync.go:346).
  - zapret 1: сервер (`/updates/zapret`) · Яндекс (папки «Zapret <ver>», парсер уже есть —
    `yandex_zapret.go`) · GitHub (Flowseal releases, логика из `cmd/download-zapret.ps1`) · прокси.
  - zapret 2: сервер (`/updates/zapret2`, SHA из манифеста); GitHub/прокси — только если
    у апстрима появится Windows-ассет (сейчас нет — источники деградируют к серверу).
- R5. zapret2 (объём из развилки Q1 — базовый): третья строка в панели «Обновления»,
  версия из `/updates/zapret2`, скачивание с SHA-проверкой, распаковка в `<exeDir>\zapret2\`
  с бэкапом/откатом как у InstallFromZip; движок zapret 1 не переключается.
- R6. Трей-флаги и модалки скачивания работают с выбранным источником прозрачно
  (фронт передаёт ничего — источник читается на бэке из config).
- R7. Все строки i18n, токены дизайн-системы; ответы okResp/errResp; маршруты через api.js.

## Не-цели

- Переключение активного движка на winws2 (портирование `zpui_2_test` — отдельная спека
  по решению владельца).
- Серверное зеркало win-bundle для zapret2 (серверная задача, отдельный деплой ZPUI-Server).
- Изменение текущего авто-поведения проверок при старте/раз в час (гейт auto_update_check).

## Критерии приёмки

- A1. Селектор в панели «Обновления» переключает Авто/ZPUI Live/Яндекс/GitHub/Гитхаб-прокси,
  выбор виден после перезапуска (config.updates_source).
- A2. Источник «ZPUI Live»: обе строки скачиваются только с сервера; сервер недоступен →
  понятная ошибка, тихого фолбэка нет.
- A3. Источник «GitHub»: zapret качается из релизов Flowseal; ZPUI — из релизов ZPUI c
  сверкой checksums.sha256 (ассет появляется в следующем теге); прокси-источник = те же
  URL через gh-proxy.com (ретрай ghfast.top).
- A4. «Авто»: сервер недоступен → ZPUI берётся с Яндекса, zapret — Яндекс→GitHub; при
  живом сервере всё идёт с сервера (приоритет ZPUI Live).
- A5. Строка ZAPRET 2 показывает версию сервера, кнопка скачивания кладёт пакет в
  zapret2\ с SHA-проверкой; движок и служба zapret 1 не затрагиваются.
- A6. Трей-кнопки обновлений и модалки работают без изменений контракта событий.
- A7. go vet/test, npm build, build.bat — зелёные; unit-тест на выбор источника
  (порядок фолбэка в авто-режиме) и на парсер GitHub-релиза.

## Развилка Q1 (владельцу): объём zapret2 в этом релизе

1. **Канал доставки (базовый, описан в R5)** — строка+скачивание+распаковка в zapret2\,
   движок не трогаем.
2. **Канал + движок** — портировать из `../zpui_2_test` детект `bin/winws2.exe` и запуск
   winws2-стратегий (+ тумблер движка в эксперт-настройках). Замечание: сервер сейчас
   раздаёт Linux-архив — до серверной раздачи win-bundle движку нечего ставить.
3. **Только отображение** — версия zapret2 в панели и скачивание файла «как есть».
