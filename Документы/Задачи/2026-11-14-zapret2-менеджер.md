# Только zapret2: менеджер запрета, служба-мониторинг, без мастера и выбора движка

> Директива владельца 14.11.2026: движок zapret1 (Flowseal) и выбор движка убираются
> полностью — работаем только с zapret2. Весь функционал запрета 2 управляется
> менеджером (единый модуль), приложение работает с запретом только через менеджер.
> Менеджер получает мониторинг в службе ZPUI (ZPUI-Service следит за winws2 и
> поднимает его). Запрет не входит в установщик/обновлятор (выполнено 13.11 —
> подтверждено). Мастер первого запуска убирается; если движка нет при запуске —
> приложение само скачивает zapret2 из авто-источника. Протестировать: запуск,
> установка, обновление, выключение, автозапуск, стратегии, логи.
> Отменяет решение 13.11 о выборе движка (спека 2026-11-13-engine-choice.md).
> Бекап: snap-20261114-094525.

## Проблема

После спеки 13.11 приложение поддерживает два движка (zapret Flowseal + zapret2),
выбор — модалка на старте внутри мастера первого запуска. Это лишняя развилка:
продукт движется на zapret2 (WinDivert 2.2, Lua-стратегии), legacy тянет второй
канал обновлений (Flowseal GitHub/Яндекс), второй набор обязательных файлов и
ветки в менеджере, установщике и UI. Служба ZPUI (zsvc) сегодня не знает о
движке: следит только за ZPUI.exe, при краше приложения сама гасит winws.exe —
запрет2 никто не мониторит и не поднимает (кроме ручного восстановления
приложением).

## Цель

Единственный движок — zapret2. Вся работа с движком — через менеджер запрета
(модуль `internal/zapret`, очищенный от legacy-веток). Служба ZPUI мониторит
движок и поднимает его. Первый запуск без мастера: нет движка — тихое
авто-скачивание zapret2 с прогрессом на стартовом экране.

## Требования

- R1. Движок zapret1 (Flowseal, winws.exe) убран: каналы установки/обновления,
  обязательные файлы, детект версии по service.bat, выбор движка в UI и config
  (`zapret_engine`), биндинг SetZapretEngine с параметром движка.
- R2. Менеджер запрета (`internal/zapret`) — единственная точка управления
  zapret2: запуск/стоп/стратегии/установка/обновление/списки/служба. Прямые
  манипуляции приложением с процессами движка (taskkill winws) переведены на
  методы менеджера. Имена на сервер уходят всегда с припиской «ZP2 ».
- R3. Служба ZPUI мониторит запрет2: (а) на службе «zapret» включается
  SCM-recovery (перезапуск при сбое процесса); (б) watchdog ZPUI-Service
  отслеживает winws2 и поднимает службу «zapret», если процесс погиб при
  включённом автозапуске службы; состояние движка видно в статусе службы
  (named pipe `status`).
- R4. Авто-скачивание zapret2: если дистрибутив отсутствует/повреждён при
  запуске — приложение скачивает его само по updates_source «auto»
  (сервер + GitHub bol-van/zapret2, побеждает свежая версия), ставит, ставит
  службу и запускает. Прогресс — на стартовом экране, без вопросов пользователю.
- R5. Мастер первого запуска (SetupWizard) и модалка выбора движка
  (EnginePickerModal) удалены; шаги настроек/аккаунта в них — не переносятся
  (тема/аккаунт настраиваются в основных экранах). `wizard_done` из config/api
  убирается.
- R6. Установщик и обновлятор не содержат запрет (подтверждено 13.11, сохранить
  гард сборки); инфраструктура zapret-дерева в pkginst демонтируется;Setup
  больше не распаковывает zapret даже при наличии в пакете.
- R7. Обновление zapret2 в UI: карточка обновлений работает по zapret2-каналу
  (проверка — сервер+GitHub; скачивание — архив zapret2; установка — dist с
  overlay). Панель версий/заметки zapret2 — из серверного зеркала, при
  отсутствии данных UI не показывает legacy-версии.
- R8. Восстановление (recovery фазы 1–3, авто-перекачка файлов, FullReinstall)
  работает только на zapret2: архивы (zapret-last.zip и PendingBackup) и сеть.
  Архивы без winws2.exe отвергаются.
- R9. Миграция с legacy-установки: при старте дистрибутив без winws2.exe
  считается отсутствующим → авто-установка zapret2 в тот же каталог
  (пользовательские списки сохраняются); процессы winws.exe гасятся.
- R10. HVCI-диагностика сохраняется (R-000-HVCI актуален для WinDivert 2.2).
- R11. Серверное зеркало /updates/zapret2 обязано отдавать корректный релиз
  (тот же архив, что апстрим GitHub bol-van/zapret2): сверка версией, SHA-256
  и виндовыми бинарниками x86 + x86_64 (решение владельца 14.11.2026).
  При расхождении — правка на сервере.
- R12. Установка движка архива — arch-aware: GOARCH 386 → binaries/windows-x86
  (WinDivert32.sys), amd64 → binaries/windows-x86_64 (WinDivert64.sys) —
  ZPUI-x86.exe ставит 32-битный движок.

## Не-цели

- Полный перенос менеджера в процесс службы (IPC-протокол управления движком
  через pipe) — следующая фаза; сейчас служба получает мониторинг+подъём.
- Серверные правки (зеркало /updates/zapret2 уже есть; панели версий —
  по возможности клиента).
- Автообновление zapret2 по расписанию (проверки только по существующим
  тумблерам при запуске — Бизнес-логика §8).

## Критерии приёмки

- A1. Свежая машина без движка: стартовый экран без мастера/выбора качает
  zapret2 (авто-источник), ставит службу и запускает движок; в config нет
  развилки zapret_engine.
- A2. Машина с legacy-дистрибутивом (winws.exe, нет winws2.exe): при старте
  zapret2 ставится поверх, пользовательские списки переносятся, winws.exe
  остановлен.
- A3. Все биндинги обновления запрета (check/download/apply, auto-install,
  recovery-фаза 3, FullReinstall) идут через zapret2-канал; legacy-канал
  Flowseal в коде отсутствует.
- A4. Убийство процесса winws2 при работающей службе «zapret» и включённом
  автостарте: SCM-recovery или watchdog службы ZPUI поднимает движок; статус
  службы (pipe `status`) показывает состояние движка.
- A5. В internal/app нет прямых taskkill/winws-манипуляций мимо менеджера;
  `go vet` не находит ссылок на zapret_engine/LegacyEngineName/SetupWizard.
- A6. Payload Setup/Update без zapret (гард сборки проходит); pkginst не
  содержит zapret-дерева.
- A7. UI: строка «Движок» и модалка выбора отсутствуют; карточка запрета
  обновляется по zapret2; EngineFailModal без «переключиться на прошлый запрет».
- A8. go vet/test, npm build/test, build.bat — зелёные; vitest ловит удалённые
  локали-ключи (мёртвых ссылок нет).
- A9. Сервер /updates/zapret2 = GitHub (версия, SHA-256 архива; внутри —
  binaries/windows-x86_64 и binaries/windows-x86 с winws2.exe и драйверами
  WinDivert64/32.sys). Проверено 14.11.2026: 1.0.7, sha256 547a5dce…da0928 —
  архивы байт-идентичны, правка сервера не требуется.
- A10. Установка на 32-битном процессе кладёт bin/winws2.exe (x86) +
  WinDivert32.sys; на 64-битном — WinDivert64.sys (essentialFiles/verify
  arch-aware).

## Итог

14.11.2026 — реализовано: единый движок zapret2 (legacy zapret1 выведен — каналы
установки/обновления, выбор движка в UI и config.zapret_engine, SetZapretEngine;
wizard_done из config/API), менеджер `internal/zapret` zapret2-only (strict-guard
InstallFromZip — архив без winws2.exe отвергается; KillEngineProcesses,
ResetWinDivertDrivers, имена на сервер всегда «ZP2 »), установка arch-aware
(386 → windows-x86/WinDivert32.sys, amd64 → windows-x86_64/WinDivert64.sys).
Служба ZPUI мониторит движок: SCM-recovery на службе «zapret» + engineWatch в
watchdog (два подряд мёртвых тика → net start zapret, cooldown 90с), состояние
движка (installed/autostart/running/revives/last_revive) в IPC-статусе. Мастер
первого запуска (SetupWizard) и модалка выбора (EnginePickerModal) удалены;
стартовый экран без движка сам качает zapret2 (auto: сервер + GitHub, побеждает
свежая версия), ставит службу и запускает. Обновлятор/установщик — без запрета
(pkginst zapret-дерево демонтировано, гард сборки сохранён). Обновление запрета —
карточка «ZAPRET 2» (обычный download/apply), EngineFailModal — «Переустановить
запрет», ZapretRestart + /api/zapret/restart. Верификация A9: зеркало
/updates/zapret2 = GitHub v1.0.7 байт-в-байт (sha256 547a5dce…da0928, внутри
windows-x86_64 и windows-x86) — правка сервера не потребовалась.

Отклонения от плана:
- killImage убран из handleCrash (watchdog zsvc): при краше приложения winws2
  больше не гасится — движок переживает краш; обоснование: он под контролем
  SCM-recovery + engineWatch, а гашение вызывало войну за процесс между службой
  «zapret» и watchdog ZPUI-Service.
- recommendedVer снят с карточки запрета (R7): панель версий zapret2 — только из
  серверного зеркала, без рекомендованных legacy-версий.
- gofmt-фиксы по тронутым файлам (не влияют на поведение).

Проверки: go build/vet/test ./... зелёные (всё дерево + GOARCH=386), npm build +
vitest 97/97, build.bat EXIT=0; тесты с гардом ZPUI_TEST_NO_SYSTEM систему не
трогают. Доки: CHANGELOG.md (v2.1.0), CHANGELOG-DEV.md, Бизнес-логика
(§2/7/7.1/7.2/8.1/8.5), Функции (§11), Архитектура (§4.3/4.5/4.15/§5/§8).
