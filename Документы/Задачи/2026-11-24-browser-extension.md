# Браузерное расширение ZPUI: анализатор доменов + пульт приложения

## Проблема

Юзер заходит на сайт (например, YouTube) без обхода или с нерабочим обходом —
страница грузится частично: часть ресурсов (CDN, API, плееры) молча падает.
Непонятно, что именно заблокировано. Добавлять домены в пользовательский список
обхода приходится вручную, вслепую. Управлять ZPUI из браузера (поменять
стратегию, включить DNS) тоже нельзя — надо переключаться в приложение.

## Цель

Расширение для Chromium-браузеров (Chrome, Яндекс, Opera, Edge и прочие форки),
работающее **только в связке с приложением** (самостоятельный режим обхода
отменён владельцем):

1. **Анализатор.** Плагин видит, какие запросы страницы упали, находит все
   хосты, с которыми сайт работает, пробует каждый и составляет список
   заблокированных ресурсов сайта. Список (по подтверждению) уходит в
   приложение — в пользовательский список обхода `list-general-user.txt`.
   После применения плагин перепроверяет: что заработало, что нет; для
   сломанного показывает тип блокировки и советует смену стратегии/запуск
   движка. Нет сети — помнит и доигрывает сценарий при её появлении.
2. **Пульт.** Мини-дашборд приложения в popup: статус движка, текущая
   стратегия (+ переключение), DNS, SOCKS-прокси, автоподбор, старт/стоп,
   трафик, доступность, хвост логов.
3. **Дистрибуция силами приложения.** Пакет расширения живёт на сервере рядом
   с обновлениями ZPUI; приложение качает его и по кнопке «Установить»
   показывает выбор браузеров (где уже стоит — выбраны автоматически) и
   ставит/обновляет расширение в выбранные браузеры (external extensions,
   реестр Windows).

## Связь с приложением

Локальный MCP-сервер приложения (`127.0.0.1:8930`, JSON-RPC `tools/call`,
Bearer-ключ) — существующий внешний интерфейс (спека 2026-11-12-mcp-server.md,
R10). «Служба ZPUI» (ZPUI-Service.exe, named pipe) браузеру недоступна.
Спаривание: юзер включает MCP в модалке приложения и вставляет ключ (или
готовый JSON-конфиг) в настройки расширения.

Ключевое свойство: движок перечитывает hostlist-файлы при изменении — ответ
`add_user_hosts` = «применено», рестарт движка не нужен.

## Требования

### Расширение (ZPUI-Extension)

- R1. Manifest V3, чистый JS без сборки; загружается в Chrome/Яндекс/Opera/Edge.
- R2. Связь: POST `http://127.0.0.1:<порт>/mcp` с Bearer-ключом; host_permissions
  `http://127.0.0.1/*` покрывает авто-сдвиг порта 8930..9020.
- R3. Мониторинг: webRequest onErrorOccurred/onCompleted — хосты по вкладкам;
  классификация кодов: `ERR_NAME_NOT_RESOLVED` → DNS;
  `ERR_CONNECTION_RESET/TIMED_OUT/TUNNEL_CONNECTION_FAILED/EMPTY_RESPONSE` →
  блокировка (DPI); `REFUSED/ADDRESS_UNREACHABLE` → недоступен;
  `BLOCKED_BY_CLIENT` → другое расширение, игнор.
- R4. Детект: ≥N упавших запросов на вкладке (клапан в настройках) → авто-проба
  в фоне → бейдж «⚠» + баннер в popup (добавление — только по кнопке).
- R5. Анализ: собрать хосты, с которыми страница работала (CDN/API/скрипты),
  проба каждого из воркера (`fetch HEAD no-cors` + таймаут; своя ошибка видна в
  webRequest с точным кодом). Итог: список заблокированных по сайту.
- R6. Применение: список с чекбоксами, «уже в списке» через `get_user_list` →
  кнопка → `add_user_hosts` → перепроверка (несколько раундов с backoff
  до ~60 с) → отчёт: X работают / Y нет.
- R7. Диагноз: для сломанных `check_resource` (тип блокировки) → уведомление
  «На стратегии <имя>: <host> — <тип>»; частично сломано → предложить
  `run_autoselect`; всё сломано при running движке → сменить стратегию;
  движок stopped → кнопка «Запустить движок».
- R8. Офлайн: `navigator.onLine` + ошибки fetch → бейдж «офлайн», поллинг стоп,
  отложенный сценарий в chrome.storage.local; по `online` — доиграть.
- R9. Пульт: статус движка, стратегии (`list_strategies`/`set_strategy`),
  движок старт/стоп/перезапуск, автоподбор, DNS, SOCKS, трафик (`get_status`),
  доступность (`get_availability` 24 ч), логи (`get_logs`, свёрнуто).
- R10. UI: токены дизайн-системы приложения, light/dark, i18n ru/en
  (chrome.i18n), только `chrome.storage.local` для настроек/кэша.

### Приложение (ZPUI)

- R11. MCP: допуск Origin `chrome-extension://*` (DNS-rebinding-защита для
  http/https-origin сохраняется; авторизация — по-прежнему Bearer-ключ).
- R12. Новые MCP-инструменты: `add_user_hosts{hosts[]}` (валидация хоста,
  поверх AddHostsToUserList); `get_user_list{}` (только list-general-user.txt);
  `check_resource{url}` (поверх CheckResource); `get_socks_status{}`
  (поверх GetSocksStatus).
- R13. Установка/обновление расширения силами приложения: детект браузеров
  (chrome/edge/Яндекс/opera/brave/vivaldi), запись `HKCU\Software\<Vendor>\
  <Browser>\Extensions\<ID>` со значениями `path` = `<install>\components\
  extension\zpui-extension.crx` и `version`; стабильный ID через `key` в
  manifest.json; «уже стоит» = запись существует → авто-выбор в диалоге;
  обновление = замена пакета + подъём версии в реестре (браузер подхватывает
  при старте); удаление = удалить записи. Предупреждение «применится после
  перезапуска браузера». Кнопка «Включить» открывает `<браузер>://extensions/
  ?id=<ID>` — Chromium ставит внешнее расширение не из магазина отключённым,
  пользователь включает его один раз.
- R14. Обновление пакета с сервера как у приложения: манифест версии →
  скачивание → проверка SHA-256 (без хеша не ставим) → замена пакета →
  перерегистрация в браузерах, где уже стоит.
- R15. UI приложения: модал/секция «Браузерный плагин»: текущая/доступная
  версия, статусы по браузерам, Установить/Обновить/Удалить; api.js, i18n ru/en,
  токены, okResp/errResp.
- R16. Сборка: `versions.txt` → `extension=`; build.bat подписывает CRX
  утилитой `ZPUI-Extension\tools\mkcrx.go` (падает при расхождении версии с
  manifest.json) и кладёт его в `components\extension\` дистрибутива;
  `knownComponents` в чистильщике пополняется `extension`.

### Сервер (ZPUI-Server)

- R17. Выкладка пакета расширения и манифеста версии рядом с существующими
  `/updates/*` статик-файлами (по образцу zpui/zapret), без новых сущностей
  в БД.

### Установщик (добавлено 25.11.2026, решение владельца)

- R18. Отдельный установщик `ZPUI-Extension-Setup.exe` (cmd/extsetup, Wails
  по образцу cmd/setup): окно с галочками найденных браузеров (где уже
  стоит — помечено), Установить / Удалить / «Открыть страницу расширений»;
  флаги `-silent` (без UI, все найденные браузеры или `-only id1,id2`) и
  `-target` (песочница, без реестра). Пишет пакет в
  `%LOCALAPPDATA%\ZPUI\extension\zpui-extension.crx` и регистрирует его —
  можно ставить и обновлять плагин отдельно от приложения.
- R19. Обновление как у приложения: сервер в манифесте выпуска отдаёт
  `setup{file,sha256,size}` и раздаёт `/updates/extension/setup`; приложение
  скачивает установщик, проверяет SHA-256 и запускает его тихо
  (`-silent -only <браузеры, где уже стоит>`); без setup в манифесте —
  прежний путь (прямо CRX).
- R20. build.bat: после сборки CRX собирает установщик со встроенным
  свежим пакетом → `components\extension\ZPUI-Extension-Setup.exe` (amd64).
- R21 (25.11.2026). Панель обновлений приложения: строка «Плагин браузера» —
  версия, «актуально» / «доступна X» / «Установить», кнопка запускает то же
  обновление (скачивание установщика с сервера и тихий запуск).
- R22 (25.11.2026). CRM → Обновления: раздел «Расширение браузера» — выпуск,
  версии/хеши файлов, форма выкладки (версия, описание, .crx, опционально
  .exe установщика), удаление выпуска; хендлеры crm/handlers_extension.go.

## Не-цели

- Самостоятельный обход блокировок внутри браузера (режим 1 отменён владельцем).
- Native Messaging, публикация в сторах браузеров.
- Принудительное включение расширения без участия юзера (корпоративная
  политика ExtensionInstallForcelist: нужны права администратора и статус
  «управляется организацией»).
- Удаление доменов, аккаунт, обновления приложения, телеметрия через MCP.
- Автоспаривание ключа MCP без участия юзера (ключ копируется из модалки).
- Поддержка Firefox/Safari.

## Критерии приёмки

- A1. `tools/call add_user_hosts {"hosts":["test.example"]}` с ключом и
  `Origin: chrome-extension://abc` → 200, хост в `list-general-user.txt`;
  повторный вызов → `added: 0, skipped: 1`; `Origin: http://evil.com` → 403.
- A2. `tools/call get_user_list` отдаёт `{hosts, count}` только из
  list-general-user.txt; `check_resource https://...` — отчёт с BlockType.
- A3. `go vet ./...`, `go test ./...` (ZPUI, ZPUI-Server) — проходят; `cd web
  && npm run build` — проходит.
- A4. Расширение в Chrome (load unpacked): спаривание по ключу из модалки MCP;
  popup показывает статус/стратегию, совпадающие с `get_status`; смена
  стратегии из popup меняет её в приложении.
- A5. Сценарий: движок стоп → проблемный сайт → баннер анализа → список
  заблокированных → «Добавить» → хосты в приложении (Списки →
  Пользовательский) → перепроверка → уведомление с итогом и советом.
- A6. Офлайн: сеть выкл → бейдж «офлайн», задание сохранено; сеть вкл →
  сценарий доигран, уведомление пришло.
- A7. Установщик: после записи реестра и перезапуска Chrome/Яндекс расширение
  появляется с стабильным ID; замена папки = новая версия после рестарта
  браузера; в диалоге уже-установленные браузеры выбраны автоматически.
- A8. Обновление: манифест на сервере с версией выше локальной → приложение
  видит, качает, «Установить» → диалог браузеров → замена.
- A9. Доки: SKILL.md (mcp) дополнен тремя инструментами; CHANGELOG.md /
  CHANGELOG-DEV.md / versions.txt / README-карты обновлены.

## План

- `internal/mcpserver/server.go` — isExtensionOrigin в authorize.
- `internal/app/app_mcp.go` — add_user_hosts / get_user_list / check_resource;
  `app_zapret_lists.go` — хелпер getUserList.
- `ZPUI-Extension\` — субпроект: manifest.json (key → стабильный ID),
  background (service-worker, mcp-client, request-monitor, analyzer, state),
  popup, options, _locales ru/en, icons, README.
- `internal\extension\` — детект браузеров, реестр, ID из key, менеджер;
  `internal\app\app_extension.go` — биндинги.
- Обновление: поверх internal/updater (манифест версии, скачивание, замена
  components\extension\).
- ZPUI-Server: статик `/updates/extension/` (пакет + манифест).
- `web\src\` — api.js маршруты + компонент модала «Браузерный плагин» +
  сайдбар-кнопка + локали.
- build.bat / versions.txt / pkginst — components\extension\.
- Тесты: mcpserver (origin), extension (ID/реестр — с skip без прав).

Риски и что показала проверка на живых браузерах (24.11.2026, Chrome 158 и
Edge 158, временный профиль): в значении `path` реестра работает только
подписанный CRX3 — папка и zip игнорируются молча (поэтому пакет — CRX, а не
папка, как планировалось сначала); CRX3 подписывается RSA PKCS#1 v1.5/SHA-256
над «CRX3 SignedData\0» + длина заголовка + заголовок + архив; внешнее
расширение не из магазина ставится отключённым (Chrome — `DISABLE_NOT_VERIFIED`,
сверка с магазином) и включается юзером один раз. Ветки Opera/Brave/Vivaldi на
живых браузерах не проверялись (на стенде их нет); ветки Chrome и Edge
подтверждены, ветка Яндекса существует в реестре. MV3-воркер живёт ~30 с —
поллинг через chrome.alarms, карта запросов — в chrome.storage.session.
