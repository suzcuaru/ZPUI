# Аудит и реструктуризация воркспейса — 30.09.2026

Статус: выполнено 30.09.2026. Карта воркспейса — [`../../../README.md`](../../../README.md).

## Исходные находки аудита

- **Мусор с объёмами**: `updater.exe` в корне репо, `build/nsitest/` (~190 МБ тестовых
  NSIS-сборок), `build/bin/ZPUI-test.exe`, `mockups/app-ui/public/bg-test.jpg`; в
  родительской папке — `ZPUI (1.8.1) (3).7z` (1,68 ГБ) и две копии `ZPUI (2.1.2)`.
- **«Бинарная витрина» гита**: репозиторий `ZPUI` использовался как витрина релизов —
  исходники в `.gitignore`, публикация бинарниками через GitHub Releases.
- **Непрокоммиченный `server/`**: серверная часть жила внутри репо `ZPUI` без своего
  git и без истории.

## Что сделано

- Воркспейс разбит на 4 проекта: `ZPUI` (клиент), `ZPUI-Server` (сервер: control/api +
  adminweb, tgbot, tgproxy, vpn/vpnctl, crm-desktop, deploy, site, metrics; свой git —
  коммиты 18ba52e, 853f9d4), `ZPUI-Mockups` (стенды UI; свой git — 894bb48, 76aabe8),
  `ZPUI-Backups` (хранилище). Репозиторий `ZPUI` остался релизной витриной (коммит
  07c9866: mockups убраны из индекса, игноры обновлены — server/, mockups/, backups/,
  updater.exe, third_party/).
- Единая система бекапов: `backup-all.bat` + `backup.ps1` в корне воркспейса,
  `backup.bat`-обёртки в проектах; хранилище `ZPUI-Backups\<проект>\snap-*`,
  ротация 5 сырых + 5 архивов на проект (только имена `snap-*`); `deploy/.env`
  включён в бекапы и исключён из гитов.
- Почищено ~2,5 ГБ мусора (список выше); NSIS-скрипты `installer/ZPUI.nsi` и
  `ZPUI-Update.nsi` не удалялись, но помечены легаси (жив только `manifest.xml`,
  используемый `build.bat`).
- Полная копия проекта до реструктуризации — `ZPUI-Backups\zpui\pre-restructure-full-20260930-1854\`
  (1,46 ГБ, с .git); исторические архивы-события — `ZPUI-Backups\archive\` (server-pre-crm,
  multinode-removed, admin-panel-removed и др., 7 шт.) + `archive\legacy-bin\`
  (APK ZPUI-Link, selfupdate.exe).
- Документация: создан README воркспейса, обновлены AGENTS.md, Документы (пути
  `server/` → `../ZPUI-Server`, `mockups/` → `../ZPUI-Mockups`), `ZPUI-Server/README.md`,
  `ZPUI-Mockups/README.md`; скиллы и агенты переведены на новые пути.

## Рекомендации

- **Не публиковать воркспейс целиком** (публичный git/облако): в нём секреты —
  `ZPUI-Backups` (включая копию `deploy/.env`) и `ZPUI-Server/deploy/.env`.
- Периодически запускать `backup-all.bat` (минимум — перед любыми правками и в конце
  дня активной работы).
- `git push` новых репозиториев (ZPUI-Server, ZPUI-Mockups) на удалённые — по
  решению владельца.
- После следующей сборки проверить, что `versions.json` обновился, и удалить
  запертые пустые папки.
