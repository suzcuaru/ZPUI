## 2. Худшие места (где структура мешает доменной работе)

1. **`internal/app` — главная точка конфликтов.** Все 12 доменов (zapret,
   proxy, tgproxy, dns, sync, devices, logs, reports, updates, setup,
   diagnostics, system) живут в одном пакете с общим `struct App`. Ограничение
   Wails: биндинги — методы `App`, поэтому домены НЕ выносить в отдельные
   пакеты; вместо этого — жёсткое «файл = домен» внутри пакета и вынос
   бизнес-логики в `internal/*`.
2. **`app_devices.go` — имя врёт:** внутри 5 доменов (devices CRUD, action
   logs, traffic snapshots, стримы автотеста/автоподбора, device-трекер).
3. **`app_api_system.go`** — 3+ домена (resources, health, user-lists,
   backups).
4. **`app.go`** — мониторы всех доменов + окно + трей + апдейты в одном файле.
5. **`config.go` (924)** — единый конфиг на все домены; sync/PeerMeta-логика
   внутри config; 70+ однотипных сеттеров.
6. **`api.js`** — ручной switch-роутинг всех вызовов: любая новая ручка =
   правка общего файла (постоянный merge-конфликт у агентов).
7. **Фронт:** `index.css` (все страницы), `App.jsx` (14 EventsOn + тосты +
   тема + recovery с проп-дриллингом `showToast`), `ZapretPage` (5 компонентов
   в файле), `StartupScreen` (машина состояний wizard'а).
8. **Дубли:** `formatBytes` (utils.js + StartupScreen + Go-аналоги в reports),
   netsh-файрвол в 3 копиях (`proxy/socks5.go:451`, `tgproxy/proxy.go:200`,
   `app_api_sync.go:88`), шаблон EventsOn/Off скопирован в каждом компоненте
   (нет `useWailsEvent`), 3 системы тултипов в index.css.

## 6. Порядок и правила

1. Волны 1 → 2 → 3; после каждой волны полные проверки + `build.bat`.
2. В одном коммите — одна волна (или один файл при крупных).
3. Не переименовывать экспортируемые методы `App` (Wails-биндинги + api.js).
4. `internal/app`: только файлы `app_*.go` / `<domain>_api.go`; никаких новых
   доменных логик внутри app — только тонкие биндинги.
5. Тесты (`config_test`, `database_test`, `strategy_test`…) переносятся вместе
   с кодом без изменений.
