# 2.0.9 итерация 2: изоляция подбора (отмена/автосмена/доступность), «эры» данных, DNS-рестарт, тексты

## Проблема (фидбек владельца после установки 2.0.9)

1. **Отмена автоподбора не останавливает прогон**: в prep-фазе (`RunAutoSelectStream`, `app_autoselect_stream.go:75-93` — dead-домены + smartPool) отмены нет вовсе (`sweepCancel==nil`, `autoTestCancel` не создан → оба вызова no-op); в фазах перебора текущий `SetStrategy` неостановим (горутина `done <- m.SetStrategy(fn)`, `autotest.go:211-213, 649-652`) → после «Отмены» движок ещё 1–2 раза холодно переустанавливает службу; гонка `setSweepCancel(nil)` → `beginAutoTest`.
2. **Автосмена срабатывает во время подбора**: гард-флаг `autoTestActive` поднимается только в `beginAutoTest` (финальная фаза, `autotest.go:525`), весь свип слеп: `autoSwitchTick` (`app_autoswitch.go:48`), серия подтверждения (`:99`), хук после смены стратегии (`app_monitors.go:84`), health-recovery (`:536`), смена оператора (`:562`), `notifyStrategyApplied` (`manager.go:118`). Плюс `autoSwitchTick` не проверяет `GetAutoSwitchEnabled()` — тумблер автосмены не отключает её.
3. **Доступность на дашборде работает во время подбора**: хук `scheduleResourceCheckAfterStrategyChange` (`app_monitors.go:81-89`) стреляет на каждого кандидата свипа → замеры под промежуточными (плохими) кандидатами портят данные и будят автосмену. Требование владельца: во время подбора доступность не работает; первый такт — через 5 сек после активации движком стратегии-победителя.
4. **«Смешивание эр» данных подбора**: `operator_strategies` копит JSON-результаты разных прогонов навсегда; этап 1 (фильтр по ключ. ресурсам) пишет только `availability_pct`, старые JSON остаются; отрезанные не получают ранг; стратегиям вне прогона данные остаются от прошлых эр. Целевая модель (владелец): ручной прогон (сайдбар) после завершения стирает прошлые данные оператора и оставляет только собранное этим прогоном; стартовая соло-проверка и ПКМ обновляют только свою стратегию; провайдер-данные не трогаются; не попавшие в прогон → «непроверенные» без данных; отрезанные фильтром → ранг D; проверка старше 7 дней → модалка с кнопкой открытия подбора.
5. **Перезапуск приложения сбрасывает системный DNS** (тест владельца): `Shutdown` ВСЕГДА снимает DNS (`app.go:676-695` → `xboxDns.Disable()`), старт НИКОГДА не переприменяет (автозапуска DNS не существует, `app.go:477-502`), `dnsVerifyApplied` (`app_api_xboxdns.go:734-743`) после этого молча сбрасывает `enabled=false`. `persistDnsPrevious` не вызывается после `Disable()` — снимок устаревает.
6. **Тексты**: «ссылка ниже» под QR при ссылке выше (`profile.tunnelScan`); 8 живых серверных кодов auth-ошибок без ключей локалей (raw-коды на экране); «минимум 6 символов» при клиентской проверке на 8 (`auth.err.weak`); «молния в боковой панели» при кнопке «Автоподбор» (ru:104, ru:623); «Подбор игровой» вместо «Игровой подбор» (ru:1146). Текст «Неверный логин или пароль» — нейтральный by design (сервер намеренно не различает, анти-енумерация) — НЕ менять.
7. **Мелочь**: миграция тиров в StrategiesTab — если первый GET /api/config упал, миграция не повторяется до рестарта (`.catch(()=>{})`, эффект `[]`).

## Цель

Отмена реально останавливает прогон; во время подбора автосмена/доступность/health-recovery не вмешиваются, первый такт доступности — через 5с после победителя; данные стратегий соответствуют последнему ручному прогону (эры не смешиваются); DNS переживает перезапуск приложения; тексты соответствуют экрану.

## Требования

- R1. Отмена (`CancelAutoTest`) работает во ВСЕХ фазах прогона: prep, свип, финал; после отмены не происходит новых применений стратегии (текущий in-flight SetStrategy — допустимо дождаться, новых не начинать).
- R2. На весь прогон (prep+свип+финал) действует единый флаг «идёт подбор»: автосмена (тик, серия, применение), хук проверки после смены стратегии, health-recovery, смена оператора — не срабатывают.
- R3. `autoSwitchTick` не работает при выключенном тумблере автосмены (`GetAutoSwitchEnabled`).
- R4. Во время подбора плановые такты доступности не выполняются и в историю не пишутся; после применения стратегии-победителя первый такт доступности — через 5 сек; далее штатный график.
- R5. Ручной прогон (mode=smart|full через сайдбар-модалку, не missingOnly, не onlyStrategy, не startup) по завершении: (а) участникам прогона — данные текущего прогона (JSON+pct+tested_at свежими); (б) отрезанным фильтром (этап 1) — явный маркер отрезанности, грейд D; (в) остальным стратегиям оператора — очистка данных проверок (`auto_test_results=''`, `tested_at=NULL`, `availability_pct=-1`), статус «непроверенная»; (г) use_count/is_active/last_source/applied_at (история применений) сохраняются; (д) таблицы провайдера/ресурсов/оператора не трогаются.
- R6. Метка последнего ручного прогона пишется для smart и full (app_flags `full_sweep_last_at`), экспонируется фронту; если прошло >7 дней — дашборд показывает модалку «пройдите подбор» с кнопками «Запустить подбор» (открывает модалку подбора) и «Позже» (до конца сессии).
- R7. При старте, если DNS включён в конфиге но не применён в системе — приложение переприменяет DNS (ретраи ~3×10с); при неудаче флаг НЕ сбрасывается, ретрай повторяется при появлении сети (netwatch); `dnsVerifyApplied` больше не гасит включённый флаг; после `Disable()` в Shutdown снимок `persistDnsPrevious` обновляется.
- R8. Тексты: tunnelScan «выше»; auth.err + ключи bad_keyword, weak_password, bad_nick, bad_keyword_len, recovery_unavailable, totp_required, totp_already, token_unknown_or_expired (ru/en); weak «6»→«8»; «молния»→«Автоподбор» (2 ключа); «Подбор игровой»→«Игровой подбор».
- R9. StrategiesTab: при неудаче GET /api/config — ретрай (до 3 попыток), миграция тиров не теряется.

## Не-цели

- Не различаем «неверный логин» vs «неверный пароль» на сервере (анти-енумерация, `ZPUI-Server` не трогаем).
- Не трогаем `strategy_games` (глобальная игровая таблица — отдельное решение).
- Не меняем серверные коды ошибок и формат API-ответов.
- «Кривое первое открытие вкладок» и «слетевшее после апдейта» — не дефекты (расследование: апдейт корректен, данные целы; это пустой apiCache + новые дефолты тиров) — правок кода нет, объяснение владельцу в отчёте.

## Критерии приёмки

- A1. `go vet ./...`, `go test ./...`, `npm run build`, `npm test` — зелёные.
- A2. «Отмена» в prep-фазе (во время dead-доменов/умного пула) останавливает прогон, события прекращаются, модалка закрывается без продолжения свипа.
- A3. Во время свипа: `autoSwitchTick` выходит сразу; `doResourceCheckAndSave` по хуку смены кандидата не пишёт записей в `resource_availability`; health-recovery/смена оператора не срабатывают.
- A4. После применения победителя: первый такт доступности через ~5с (±2с), затем график живёт.
- A5. После ручного smart/full прогона: участникам — свежие tested_at; отрезанным — грейд D; остальным оператора — «непроверенные» (пустой JSON, pct=-1); `operator_info`/`resource_availability`/`current_operator` не изменились.
- A6. Стартовая проверка и ПКМ-тест меняют данные только своей стратегии (база нетронута).
- A7. Через >7 дней после прогона (поле в статусе) дашборд показывает модалку; кнопка открывает модалку подбора; «Позже» скрывает до рестарта.
- A8. Рестарт приложения при включённом DNS: DNS в системе применён после старта (панель «в системе» не пустая, иконка горит); при отсутствии сети флаг остаётся включённым, применяется после появления сети.
- A9. Все тексты R8 в обеих локалях; `weak` соответствует проверке длины.
