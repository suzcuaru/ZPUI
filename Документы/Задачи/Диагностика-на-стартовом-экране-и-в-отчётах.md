# Сервер: секция диагностики в отчётах (инжест + CRM)

> Задача для агентской сессии — **только сторона `../ZPUI-Server`** (control API
> + adminweb/CRM). Клиентская часть (автодиагностика на стартовом экране,
> модалка критичных проблем, отправка секции) уже реализована в ZPUI и
> отправляет данные в существующий `report.upload`.
> Дата постановки: 21.10.2026.

## Что приходит в отчёте

К отчёту `report.upload` добавлена секция **`diagnostics`** верхнего уровня
(рядом с существующими секциями снапшота):

```json
"diagnostics": {
  "checked_at": "2026-10-21T12:34:56+03:00",
  "checks": {
    "zapret_service": { "status": "ok",    "label": "Служба Zapret",      "detail": "Работает" },
    "windivert":      { "status": "error", "label": "WinDivert",          "detail": "Не найден" },
    "vpn":            { "status": "warn",  "label": "VPN сервисы",        "detail": "AdaptX, ..." },
    "...":            { "status": "ok|warn|error", "label": "...", "detail": "..." }
  }
}
```

Ключи проверок (полный набор): `bfe_service`, `zapret_service`, `windivert`,
`winws_process`, `tcp_timestamps`, `firewall`, `system_proxy`, `conflicting`,
`killer`, `intel`, `checkpoint`, `smartbyte`, `adguard`, `vpn`, `dns`,
`hosts_file`, `proxy`. Статусы: `ok` / `warn` / `error`. `label`/`detail` —
русские человекочитаемые строки с клиента (при необходимости CRM может
подменять их своими словарями по ключу `key`... ключ `key` в checks сейчас
отсутствует — если понадобится словарь по ключам, добавить на клиенте; пока
CRM достаточно рендерить label/detail как есть).

Обратная совместимость: секция может отсутствовать (старые клиенты, отчёты до
внедрения) — просто не показывать вкладку.

## Задача 1. Инжест в control API

- В обработчике `report.upload` добавить разбор `diagnostics`: сохранять
  целиком как JSONB (например, колонка `reports.diagnostics` или отдельная
  таблица `report_diagnostics` с `report_id`, `checked_at`, `checks` JSONB).
- Отсутствие секции — валидный случай (NULL), ошибкой не считать.
- Объём: ≤ ~20 проверок на отчёт, индексация не нужна; достаточно STORED JSONB.

## Задача 2. Модалка просмотра отчёта в CRM (adminweb)

- В модалке отчёта — новая секция/вкладка **«Диагностика»**:
  - таблица проверок: статус цветом (`ok` — зелёный, `warn` — янтарный,
    `error` — красный), `label`, `detail`;
  - шапка секции: время прогона `checked_at` (локальное время машины клиента);
  - сортировка: сначала `error`, затем `warn`, затем `ok`.
- Секция скрыта, если данных нет.
- Стили — токены CRM (adminweb), не клиентские.

## Приёмка

- [ ] Новый отчёт с клиентской секцией диагностики сохраняется, секция видна в CRM-модалке.
- [ ] Старые отчёты без секции открываются как раньше, без ошибок инжеста.
- [ ] Проверки `deploy`/прогон CRM на стене (`Tailscale`, DEMO_MODE при необходимости).
