# Задача 18.10.2026: исключения v5, batch-протокол, отчёты/DNS, прокси-статика

Утверждённый оркестратором контракт. Все агенты работают строго по этому документу;
расхождение контракта = эскалация оркестратору, а не самодеятельность.

## 1. Система исключений (вместо старой)

Два файла исключений доменов в `zapret/lists/`:

| Файл | Кто владеет | Как обновляется |
|---|---|---|
| `list-exclude-system.txt` | Приложение (системный) | Вшит дефолтом (go:embed), создаётся если нет; целиком заменяется при смене версии с сервера |
| `list-exclude-user.txt` | Пользователь | Уже существует как пользовательский список дистрибутива: если нет — создаётся пустым/дефолтным, если есть — НЕ трогается никогда |

- Стратегии ДОПАЗНУЮТСЯ к файлам через инжект в `parseStrategyArgs`: при наличии
  `list-exclude-system.txt` добавлять `--hostlist-exclude="%LISTS%list-exclude-system.txt"`
  в КАЖДУЮ секцию winws (после последнего существующего `--hostlist-exclude=...` в секции;
  секции разделяются `--new`). Файлы дистрибутива `list-exclude.txt` / `list-exclude-user.txt`
  остаются как есть и в аргументах не меняются.
- **Старый конвейер исключений v4 (pending→confirmed→alive) и его файл — СНЕСТИ**: клиент
  больше не пишет серверные исключения в списки дистрибутива. `serverListTargets`
  (app_v5.go: general/exclude) — удалить: серверные general/exclude списки больше НЕ применяются.
- Домен считается мёртвым — проверка существующая (blockcheck/ytcheck-стек). Все найденные
  мёртвые домены попадают в **пользовательский** файл `list-exclude-user.txt`
  (append, с дедупликацией; комментарий-заголовок `# добавлено автоматически`).

## 2. Протокол v5: один batch-запрос

Вместо пачки периодических запросов — один оп `state.sync` (POST /api/v5, тот же конверт):

Request body: `{ "have": { "exclusions": <int64 локальная версия>, "resources": <int64> } }`

Response data:
```json
{
  "account": {...v4AccountInfo, может быть null},
  "subscription": {...v4Subscription, может быть null},
  "banned": false,
  "exclusions": { "version": 1840123, "unchanged": false, "items": ["dead.example", "..."] },
  "resources": { "version": 1792321313 }
}
```
- `unchanged:true` → `items` может отсутствовать, клиент оставляет файл как есть.
- `resources` — только ВЕРСИЯ набора (для отображения); списки general/exclude сервер больше не отдаёт.
- Клиентский цикл: старт + раз в час (вместо 6ч). Один запрос заменяет: state.get, resources.sync,
  синк исключений. Профиль/подписка кэшируются как раньше.

## 6. SOCKS-прокси и статика по подсетям

Config (config.json):
- `proxy.enabled` (bool, default **false**) — мастер-тумблер SOCKS.
- `proxy.static_subnets` — map ключ `"a.b.c.d/len"` → `{ "ip": "...", "mask": "...", "gw": "..." }`
  (запомненная статика сети). Ключ = подсеть текущего IPv4.

API (контракт для web):
- `GET /api/socks/status` + поля: `enabled`, `static_ip` (факт адаптера), `current_subnet`,
  `static_subnets` (map), `static_conflict` (`{"subnet": "...", "ip": "..."}` | null), `lan_ip`, `port`, `running`.
- `POST /api/socks/enabled` `{on}` — включение требует активной статики: если для текущей
  подсети нет статики → `errResp("static_required")`.
- `POST /api/socks/static-ip` `{on}` — вкл: снять текущие ip/mask/gw → netsh static → запомнить
  в `static_subnets[подсеть]`; выкл: netsh dhcp (запись в map сохраняется).
- `POST /api/socks/static-set` `{ip, mask, gw}` — задать статику вручную (диалог конфликта),
  валидация ip/mask/gw.
- Фоновый сторож (тик 30с, уважает internal/power): подсеть сменилась → если на адаптере была
  наша статика → netshSetDHCP; для новой подсети есть запомненная статика → проверка занятости
  адреса (ARP-проба: ping + arp -a MAC ≠ наш) → свободен: применить; занят: `static_conflict`
  + событие `socks:static-conflict` в UI, прокси остаётся выключен.

UI (ProxyPage):
- SOCKS-герой получает Switch (сейчас всегда включён). По умолчанию выключен.
- Включение SOCKS без статики: тост «Включите статический IP — прокси доступен устройствам
  только по постоянному адресу» + `static_required`.
- Блок «Статический IP»: тумблер + подпись «работает только в текущей сети (при смене сети
  статика снимается и возвращается автоматически, если сеть знакома)».
- Диалог конфликта: «Адрес X занят другим устройством в этой сети. Укажите другой статический
  адрес» + поля ip/mask/gw → `POST /api/socks/static-set`.
- Дополнительные настройки ТГ-прокси (порт, Fake TLS, CF-fallback, CF-workers) — из футер-дровер
  перенести в секцию Telegram-прокси (своршиваемый блок под hero), футер-кнопку «Дополнительно» убрать.

## 9. Уточнение 19.10 (вечер): пара «системный + пользовательский» = SKIP-РЕСУРСЫ

Владелец уточнил: «системный и пользовательский файл исключений» — это файлы
SKIP-ресурсов (исключение из проверок доступности и автоподборов), НЕ DPI-хостлисты.

- `skip-resources.txt` (рядом с config.json) — пользовательский: редактируется в UI,
  авто-допис мёртвых доменов, мигрированный контент exclusions-server.txt. Как есть.
- `skip-resources-system.txt` (рядом с config.json) — НОВЫЙ системный: вшитый дефолт
  (шапка), целиком заменяется при смене версии набора с сервера (state.sync,
  exclusions-блок — ПЕРЕНАПРАВИТЬ сюда с list-exclude-system.txt). Не редактируется
  пользователем. list-exclude-system.txt (DPI-база банки/гос, инжект в winws) —
  остаётся статической базой, сервером больше не обновляется.
- ОБОА гейта учитывают ОБА файла (union):
  - приложение: excludedHost (exclusions.go) — уже зовёт cfg.IsSkippedResource
    (skip user) + DPI-файлы; добавить системный skip-файл;
  - движок: filterSkippedTargets (internal/zapret/strategy.go, loadTestTargets →
    автоподборы, line ~707 списки стратегий) — cfg.IsSkippedResource; добавить.
  Реализация: IsSkippedResource в config.go проверяет ОБА файла (user + system).
- В CRM «Пользовательские» (reported_exclusions) клиент передаёт содержимое
  skip-resources.txt (НЕ list-exclude-user.txt): поле exclusions.user в отчёте —
  сменить источник на GetSkipResources().
- pkginst: protectedUserRel + isUserPath += "skip-resources-system.txt".
- GetSkipResources биндинг: добавить блок system {lines, count} (read-only) для UI.
- web: во вкладке Списки панель skip-resources дополняется read-only-блоком
  «Системный скип-лист» (что прислал сервер), без редактирования.
- Тесты: оба гейта видят домены из системного skip-файла; state.sync пишет в
  него; exclusions.user берётся из skip-resources.txt.
