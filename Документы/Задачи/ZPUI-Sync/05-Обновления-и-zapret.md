# 05. Обновления и zapret

## 1. Инвариант обновляемости (СВЯТОЕ)

Путь «старый клиент увидел обновление → скачал → установил» живёт **всегда, при любых
сносах**: `GET /api/v1/updates/zpui` (сервер управления) + фолбэк Яндекс.Диск.

- Этот эндпоинт **не переносится** в ZPUI Sync — бутстрап не зависит от версии протокола.
  Это страховка для этой и всех будущих миграций.
- Проверки — только при запуске, по тумблеру `auto_update_check` (бизнес-логика §8) — не меняется.
- Пакет обновления — тихий обновлятор `ZPUI-Update-<v>.exe` — не меняется.

## 2. Zapret: только сервер

**Сегодня (снос):** клиент листит GitHub-релизы (`internal/zapret/updater.go`), ходит через
зеркала-прокси gh-proxy.com/ghfast.top (`FallbackURLs`), умеет git clone
(`internal/updater/git.go`), панель «Версии Zapret» тянет списки с GitHub+Яндекс с ETag-кешем
и дедупом, юзер выбирает версию.

**Станет:**

- **Control plane:** рекомендованная версия приходит в `sync.pull`:
  `"recommended": {"zapret": {"version": "1.10.4", "url": "...", "sha256": "..."}}` —
  там же, где рекомендованное обновление ZPUI. Одна форма для обоих продуктов.
- **Data plane:** архив качается прямым HTTPS GET с сервера (uploads/), как пакет ZPUI.
  Бинарники через JSON-диспетчер sync не гоняются.
- **GitHub остаётся только на сервере** — зеркало `zapretsync.go` (цикл 6ч) уже работает
  и продолжает тянуть релизы Flowseal. Клиенты GitHub не видят никогда.
- **Механика установки не меняется:** `InstallFromZip` с бэкапом состояния и откатом.
  Меняется источник zip и источник хеша (теперь sha256 из `sync.pull`).

## 3. Снос в клиенте (чек-лист)

| Что | Где |
|---|---|
| Листинг GitHub-релизов, `FallbackURLs` (gh-proxy/ghfast) | `internal/zapret/updater.go` |
| Git-инсталлятор | `internal/updater/git.go` |
| ETag-кеш + дедуп панели версий (`gh_zapret_releases_cache.json`) | `internal/app` (панель версий) |
| Выбор версии в UI; панель «Версии Zapret» в текущем виде | `web/src` (страница Zapret) |

После сноса умирает целый класс проблем: 403 rate limit GitHub API, мёртвые зеркала,
состояние «доступно только Облако».

## 4. Панель версий после переделки

Панель вырождается в две строки + кнопку:

- «Установлено: 1.10.4»
- «Сервер рекомендует: 1.10.5» (или «у вас актуальная»)
- Кнопка «Обновить» (или «Скачать» по флагу доступности — как в трее сегодня)

**Выбора версии у юзера больше нет.** Версию назначает сервер — это управляемая раскатка:

- Публикация новой версии в зеркале → все получают одну и ту же.
- Откат = пин рекомендованной версии на предыдущую в админке сервера, без релиза ZPUI.
- Рекомендуется добавить в админку поле «рекомендованная версия zapret» (если его ещё нет
  в `zapretsync.go`) — пин поверх «последней в зеркале».

## 5. Что остаётся как есть

- Зеркало на сервере (цикл, `published_at`-сортировка).
- Обновления запрета в трее («Обновление запрета — скачать» по флагу доступности).
- `data.versions` по-прежнему честно рапортует установленную версию zapret — сервер видит
  расползание парка по версиям и может считать прогресс раскатки.
