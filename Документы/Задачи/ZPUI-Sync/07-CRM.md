# 07. CRM (adminweb)

Репозиторий: `../ZPUI-Server/control/api/adminweb`. Ядровые эндпоинты —
`../ZPUI-Server/control/api`.

## 1. Панель профиля устройства — пол-экрана с подвкладками

Сегодня: `DeviceDrawer` (`adminweb/src/pages/Devices.jsx:74`, компонент
`components/ui/Drawer`) — узкая панель со сводкой.

**Станет:** панель на **пол-экрана** (widened Drawer или переиспользование паттерна),
с **подвкладками** (таб-строка внутри панели):

| Подвкладка | Данные | Источник |
|---|---|---|
| Обзор | статус, runtime, версии, система, конфиг, оператор, трафик | upsert-таблицы (`devices`, `device_runtime`, `device_config`, `device_system`, `device_traffic`, `component_versions`, `operators`) |
| Доступность | график + таблица по ресурсам | `availability_samples` |
| Сеть | пинг/скорость, история | `network_latest` + `network_samples` |
| Стратегии | баллы по операторам, игровые | `strategy_samples`, `strategy_game_samples` |
| События и ошибки | журнал действий, auth, ошибки | `events`, `device_errors` |
| Исключения | скип-лист пользователя, версия системного | `reported_exclusions` |

Подвкладка «Отчёт» как отдельная сущность **исчезает** — «отчёт» = набор этих подвкладок,
все данные из базы. Блобов не существует.

## 2. Селектор периода

Общий селектор в шапке панели, применяется к **потоковым** подвкладкам
(Доступность, Сеть, Стратегии, События и ошибки):

- Пресеты: **Сегодня / 7 дней / 30 дней / Произвольный период** (date-range picker).
- В API — `from`/`to` (UTC); пресеты считает сервер (граница «сегодня» — по серверному дню).
- Агрегации (средняя доступность, пики, счётчики) — на сервере в том же запросе,
  чтобы CRM не таскала сырые ряды для больших окон.

## 3. Ядровые эндпоинты для CRM

Вместо `/admin/api/reports*` (парсинг блобов):

```
GET /admin/api/devices/{id}/overview                 → сборка upsert-таблиц
GET /admin/api/devices/{id}/samples?kind=availability|network|events|errors|usage
                                                     &from=...&to=...&agg=raw|hourly
GET /admin/api/devices/{id}/strategies?from=...&to=...
```

- Читают таблицы из 04, фильтр по `device_id` + окно.
- `agg=hourly` — серверная агрегация (avg/max) для длинных окон.

## 4. Кнопка «Запросить» → sync.requests

Существующая кнопка «Запросить» (свежие скипы) переезжает на новый механизм:
кладёт просьбу в `sync.requests` (`{"requests": {"now": ["exclusions"]}}`) — устройство
исполняет на ближайшем тике (≤1 мин). В UI — тот же контрол, статус исполнения виден
по свежести соответствующей секции.

## 5. Порядок переключения (чтобы ничего не сломать)

1. Новые таблицы уже наполняются (этап 2 миграции) — переключение CRM можно делать
   без спешки, параллельно.
2. Переключаются страницы, читавшие блобы: `Analytics.jsx:278-284`
   (`/admin/api/reports`, `/admin/api/reports/:id`) → новые эндпоинты §3.
3. После обновления парка (этап 4) — снос `/admin/api/reports*`,
   `adminReportsList`/`adminReportGet` (`device_reports.go`), таблиц `reports`/`device_reports`.

## 6. Прочее в CRM

- **Монитор устройств (онлайн):** presence уже обновляется на любой аутентифицированный
  запрос — онлайн-лампочка в списке устройств (`Devices.jsx`) продолжает работать,
  включая устройства, отклонённые очередью (busy).
- **Настройки сервера:** новые ключи `sync_*` (очередь) и `*_retention_days`
  (ротация) появляются на странице Settings автоматически (существующий механизм
  retention-ключей, `settings.go`).
- **Рекомендованная версия zapret:** пин/публикация в разделе Updates
  (см. 05 §4) — контроль раскатки и откат.
