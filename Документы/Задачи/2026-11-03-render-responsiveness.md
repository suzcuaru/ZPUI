# Отзывчивость рендера: модалки, кроссфейд вкладок, адаптивный tier, keep-mounted

> Продолжение работы `2026-11-03-perf-startup-tabs-dns.md` (выполнена): та закрыла
> данные (дифф статуса, SWR-кэш вкладок, async DNS). Эта — рендерный слой, который
> остался: владелец по-прежнему видит лаги при открытии модалок, смене вкладок и
> в общей плавности интерфейса.

## Проблема

### П1. Открытие модалки — самый дорогой кадр в приложении
- Оверлей на всё окно с живым `backdrop-filter:blur(10px)` (`web/src/styles/index.css:694`)
  во время входа 400 мс (`index.css:696`) — композитинг пересчитывает размытие всего
  содержимого окна каждый кадр входа.
- Карточка входит кейфреймами с **анимированным** `filter:blur(6px)→none`
  (`index.css:5865`, `modalIn`) — per-frame gaussian-blur крупного элемента поверх
  блюрящего оверлея. То же на выходе (`modalCardOut`, `index.css:5870`).
- Тосты: `blur(18px) saturate(1.4)` на каждый (`index.css:612`), тостов бывает несколько.
- На машинах, где WebView2 ушёл в программный рендер (SwiftShader — драйвер/RemoteFX/старый iGPU),
  каждый из этих эффектов дороже на порядок; признаков деградации приложение не показывает.

### П2. Смена вкладок клонирует DOM
- `navigate()` перед кроссфейдом делает `cloneNode(true)` всей уходящей страницы +
  ручную синхронизацию прокрутки по всем узлам (`web/src/App.jsx:278-288`) — блокировка
  главного потока в момент клика, на тяжёлых страницах (Monitor, Dashboard с SVG) — десятки мс.
- Старая страница размонтируется (`App.jsx:1029`, `key={activePage}`) — при возврате полная
  пересборка DOM с нуля. SWR-кэш даёт мгновенные данные, но сам монтаж страницы остаётся тяжёлым.

### П3. Нет адаптации к слабому рендеру
- GPU-ускорение WebView2 включено по умолчанию и аргументами не отключено
  (`main.go:204-208` — только анти-троттлинг флаги), однако падение в программный рендер
  не детектируется: «стеклянные» эффекты и длинные анимации применяются везде одинаково.
- Механизм упрощения уже есть — `body.power-save` глушит декоративные анимации
  (`index.css:1335`, `App.jsx:722`), но он завязан на экономный режим, а не на возможности рендера.

## Цель
Открытие модалок и переключение вкладок визуально мгновенные (без многотрудовых
композитинговых пиков); на слабых/программных рендерах интерфейс автоматически
рисуется по упрощённым правилам и остаётся плавным.

## Требования
- R1. Вход/выход модалок и тостов не анимирует фильтры размытия (keyframes без `filter:blur`);
  визуальный язык входа сохраняется (opacity/transform, семейство `--ease-soft`).
- R2. Пересчёт живого blur оверлея модалки не выполняется во время входной анимации;
  стекло применяется одним переключением после входа (не per-frame).
- R3. Радиусы blur пересмотрены вниз без потери читаемости (тосты ≤ 12px, оверлей ≤ 10px).
- R4. Смена вкладок не клонирует DOM: кроссфейд строится на реальных узлах
  (уходящая страница держится в DOM и гаснет, пустого кадра нет).
- R5. Повторное открытие вкладки не пересобирает её DOM: посещённая страница остаётся
  смонтированной (скрыта `display:none`), монтируется лениво — при первом визите.
- R6. Опросы и секундные тики неактивных (скрытых) страниц не выполняются; при возврате
  на вкладку данные обновляются немедленно. Механизм — на уровне хуков
  (`usePolling`/`useNow`), страницы правок контракта не требуют.
- R7. Если WebView2 работает в программном рендере, UI один раз при старте включает
  упрощённый режим (`render-lite`): без живых blur (включая blur кастомных тем),
  декоративные анимации глушатся как в `power-save`. На аппаратном рендере вид не меняется.
- R8. Модалки с GET-данными при повторном открытии показывают кэш мгновенно (общий SWR-кэш
  `api.js`), обновление — тихо. Первое открытие — как сейчас.
- R9. Конвенции не нарушаются: prefers-reduced-motion и power-save работают как раньше,
  i18n без изменений, окно 900–1280×650–720 не трогается, дизайн-токены без хардкода.

## Не-цели
- Отказ от «стеклянного» дизайна на аппаратном рендере — упрощение только в `render-lite`.
- Пересмотр WebView2-аргументов (`backgroundArgs` остаются) и интервалов поллинга.
- Виртуализация длинных списков (отдельная задача при необходимости).
- Контракт страниц/дерево статуса (п осталось из предыдущей спеки — не трогаем).
- Серверная часть, движок, бэкенд-интервалы.

## Критерии приёмки
- A1. В `web/src/styles/index.css` нет keyframes, анимирующих `filter:blur` (grep).
- A2. Вход модалки ≤ 340 мс, оверлей ≤ 200 мс; анимируются только opacity/transform.
- A3. `backdrop-filter` тостов ≤ 12px; в `render-lite` blur тостов/оверлеев/кастомных тем
  отсутствует (плоская полупрозрачная подложка).
- A4. `navigate()` в `App.jsx` не содержит `cloneNode`/`querySelectorAll('*')`; кроссфейд
  вкладок визуально без пустого кадра (ручная проверка).
- A5. После посещения вкладки её DOM остаётся в дереве (display:none); на активной вкладке
  в DevTools Network нет запросов неактивных (ручная проверка).
- A6. Повторное открытие модалки с GET-данными (CacheModal) рисует данные мгновенно
  из `apiCacheGet`, без ожидания сети (ручная проверка + код).
- A7. Детект рендера — чистая функция с unit-тестом (Vitest): строка SwiftShader/software →
  lite; аппаратные строки (ANGLE/D3D/Metal-подобные) → обычный режим.
- A8. Прогон: `npm test`, `npm run build` (web), `go vet ./...`, `go test ./...`, `build.bat` — зелёные.
- A9. Субъективная приёмка владельца на его машине: открытие модалок и переключение вкладок
  без заметных лагов в сборке `build/dist`.

## План

Все правки — только фронтенд (Go не затрагивается). Порядок — батчами 1→2→3,
после каждого батча `npm run build` + `npm test`.

### Батч 1 — точечные фиксы рендера
- `web/src/styles/index.css`:
  - `modalIn`/`modalCardOut` — убрать `filter:blur` (R1);
  - `.modal-overlay` — вход 200 мс (opacity only), стекло применяется через
    вторую анимацию `glassIn` с задержкой (длительность 1 мс) после входа (R2);
  - `.toast` — blur 18px→12px, saturate вниз (R3);
  - инспекция остальных `backdrop-filter` (строки 805/3965/4525/4557) —
    мелкие поверхности, радиусы при необходимости.
- `web/src/App.jsx` — удалить snapshot-слой (`cloneNode`/scroll-sync),
  кроссфейд держится на мгновенной отрисовке из SWR + fade-in 200 мс;
  полная версия «на реальных узлах» — следствием батча 3 (R4).

### Батч 2 — адаптивный tier качества
- Новый `web/src/renderTier.js`: чистая функция `detectRenderTier(str)` +
  `applyRenderTier()` (один WebGL-проб при старте, класс `render-lite` на body).
- `web/src/styles/index.css`: блок `body.render-lite` — `backdrop-filter:none`
  для всех «стеклянных» селектов (включая поверхности кастомных тем),
  глушение декоративных анимаций по образцу `power-save` (R7, A3).
- Unit-тест `web/src/__tests__/renderTier.test.js` — строки SwiftShader/
  llvmpipe/software → lite; ANGLE D3D/Vulkan → обычный (A7).

### Батч 3 — keep-mounted вкладки + кэш модалок
- `App.jsx`: рендер посещённых страниц в `PageHost` (лениво: страница
  монтируется при первом визите и остаётся, скрытые — `display:none`);
  уходящая страница при переходе остаётся смонтированной на 200 мс
  (кроссфейд реальных узлов, R4; snapshot из батча 1 не возвращается).
- Новый `web/src/hooks/usePageVisible.js` (контекст) + правки
  `usePolling.js`/`useNow.js`: неактивная страница — тики пропускаются,
  возврат на вкладку — немедленный refetch (R6). Страницы правок не требуют.
- `Modal.jsx`: модалка скрытой страницы не рисуется (портал читает контекст),
  состояние страницы сохраняется.
- SWR-кэш для модалок с GET-данными (CacheModal первым, остальные по инспекции) (R8).

### Риски
- Keep-mounted: модалка скрытой страницы снова появится при возврате на вкладку
  (сейчас закрылась бы безвозвратно) — принимается как свойство сохранения состояния.
- Скрытые подписки `EventsOn` страниц остаются активными — ревизия при реализации;
  шум (тосты из скрытых страниц) не ожидается: события тостов идут из бэкенда, не из страниц.
- Рост DOM (до 7 страниц) — без layout/paint у скрытых, память незначима.
