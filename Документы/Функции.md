# Функции ZPUI

> Документ описывает **пользовательские возможности** продукта — что конкретно может делать пользователь в интерфейсе, какие задачи решает, какие элементы UI для этого существуют. Технические детали — в [`Архитектура.md`](./Архитектура.md), доменные правила — в [`Бизнес-логика.md`](./Бизнес-логика.md), визуальный язык — в [`Дизайн-и-типографика.md`](./Дизайн-и-типографика.md).

## 2. Дашборд (`/`)

Главный экран — оперативная сводка состояния.

### 2.1. Элементы

- **Большая карточка статуса движка:** «Обход: Включён / Выключен / Ошибка» с цветовым кодированием (зелёный/серый/красный). Кнопка «Старт» / «Стоп» прямо на карточке.
- **Кольцевой индикатор доступности:** 0–100% за последнее измерение. Цветовая шкала: ≥80% зелёный, 50–80% жёлтый, <50% красный.
- **Активная стратегия:** имя карточки стратегии с возможностью перейти к смене.
- **Мини-график за час:** спарклайн доступности.
- **Состояние сервисов:** компактные бейджи «Прокси: вкл/выкл», «DNS: вкл/выкл».
- **Последнее событие:** строка из журнала (например, «AutoSwitch переключился на … 5 мин назад»).
- **Кнопка «Диагностика»:** быстрый доступ при проблемах.

### 2.2. Быстрые действия

- «Старт/Стоп» — основное действие.
- «Открыть Discord» — кнопка быстрого теста (открывает браузер на discord.com).
- Автоподбор запускается из вкладки «Стратегии» и кнопки в сайдбаре
  (окно подбора: «Умный» — сразу, «Игровой» — выбор стратегий).

## 3. Стратегии (`/strategies`)

Управление пресетами zapret.

### 3.1. Верхняя панель (Service Bar)

- Статус службы Windows (running/stopped/error)
- Кнопка старт/остановки движка
- Индикатор текущей стратегии
- Переключатель AutoSwitch (вкл/выкл)
- Кнопка настроек AutoSwitch (gear) — открывает выпадающее меню с параметрами:
  - Порог переключения (threshold %)
  - Интервал проверки (interval мин)

### 3.2. Подвкладки стратегий

Четыре подвкладки в верхней части:

- **Все** — все стратегии (алые, зелёные, жёлтые, красные)
- **Зелёные** — стратегии с доступностью ≥70%
- **Жёлтые** — стратегии с доступностью 30–69%
- **Красные** — стратегии с доступностью <30% или без данных

На каждой подвкладке — карточки стратегий с цветовой индикацией процента доступности.

### 3.3. Карточка стратегии

- Имя стратегии (и технический id)
- Процент доступности (цвет: зелёный ≥70%, жёлтый ≥30%, красный <30%)
- Бейдж «Активна» (если выбрана)
- Кнопка «Применить»

### 3.4. Автоподбор

- Кнопка «Автовыбор» открывает окно подбора с **двумя плитками**; кнопки
  «Запуск» в модалке нет:
  **«Умный»** — клик запускает подбор сразу: данные с сервера для вашего
  оператора; без сервера — локальная история стратегий этого компьютера;
  если и её нет — проверяются все стратегии;
  **«Игровой»** — открывает второй шаг: чек-лист стратегий для проверки
  (одна, несколько или все; по умолчанию отмечены все, есть «Выбрать все» /
  «Снять все») с кнопкой запуска внутри шага.
- В модалке видна строка **провайдера** (обновляется при смене сети) и
  **рейка фаз**: «Определяем провайдера → Получаем данные с сервера →
  Проверяем локальные данные → Анализируем → Запускаем подбор» (в игровом
  режиме шаг сервера пропускается).
- Показывает live-результаты (доступность, скорость, пинг, игровой балл).
- По завершении — автоматически применяет лучшую стратегию.

### 3.5. AutoSwitch

- Автоматическое переключение стратегии при падении доступности ниже порога
- Настраиваемые параметры: порог (threshold %), интервал проверки (interval мин)
- История переключений (последние 10 записей)
- Уведомление при переключении

### 3.6. Нижняя панель (FiltersPanel)

- Фиксированная внизу экрана
- Содержит фильтры для списков доменов (Discord, YouTube, пользовательский)
- Переключатели включения/отключения фильтров
- **«Оптимизация пинга»** — твики Windows для игр: TcpAckFrequency=1 и
  TCPNoDelay=1 на всех сетевых адаптерах + NetworkThrottlingIndex=0xFFFFFFFF
  (без delayed ACK/Nagle и сетевого троттлинга). Состояние читается из
  реестра (источник истины — система, не config.json); после смены сети
  (новый адаптер) нужно включить повторно. Пакет: `internal/winopt`.

### 3.7. Вкладка «Списки»

- Отдельная вкладка для редактирования доменных списков
- Аналогична предыдущему разделу «Списки доменов»

## 4. Списки доменов (`/lists`)

Редактор фильтр-списков zapret.

### 4.1. Разделы

- **Discord-список:** домены Discord.
- **YouTube-список:** домены YT + googlevideo.
- **Пользовательский список:** домены, добавленные пользователем.
- **Исключения:** домены, которые НЕ нужно трогать.

### 4.2. Операции

- Просмотр (табличный вид).
- Добавление домена (поле + кнопка; валидация формата).
- Удаление (крестик в строке).
- Редактирование (инлайн).
- Импорт из текста (вставить список → распарсить по строкам).
- Экспорт в `.txt`.
- Сброс к дефолту.

### 4.3. Сохранение

- Изменения применяются при следующем старте движка.
- `useDebouncedSave` — автосохранение через 1 сек после правки.
- Индикатор «Не сохранено» / «Сохранено».

## 5. Прокси (`/proxy`)

Управление SOCKS5-сервером для раздачи обхода.

### 5.1. Тумблер и статус

- Крупный `Switch`: Включён / Выключен.
- Статус: «Слушает на 192.168.1.10:1080» или «Остановлен».

### 5.2. Настройки

- Порт (по умолчанию 1080).
- Авторизация (вкл/выкл + поля login/password с маской).
- Привязка к интерфейсу (все / конкретный IP).

### 5.3. Подключение клиентов

- Отображение адреса `socks5://192.168.1.10:1080` (с кнопкой «Копировать»).
- **QR-код** для быстрого сканирования телефоном.
- Краткая инструкция «Как настроить на телефоне» (с раскрывающимися блоками для iOS/Android).

### 5.4. Мониторинг подключений

- Список активных клиентов (IP, длительность, объём трафика).
- Опционально — лог подключений.

### 5.5. Telegram MTProto-прокси

Встроенный Go-native мост для Telegram Desktop (MTProto → WebSocket к
Telegram DC). Работает параллельно с SOCKS5 на своём порту.

- **Тумблер и статус**: «Работает на 127.0.0.1:1443» / «Остановлен» +
  счётчики (активные соединения, отдано байт).
- **Подключение**:
  - Ссылка `tg://proxy?...` (копирование / «Открыть в Telegram»);
  - при включённом Fake TLS — дополнительная ee-ссылка (маскировка под
    HTTPS к указанному домену);
  - Secret: отображение, копирование, генерация нового.
- **Настройки**: порт, автозапуск, Fake TLS домен, резерв через
  Cloudflare (вкл/выкл), Cloudflare Worker домены.
- **Статистика** (при работе): соединения, трафик, WS успех/отказы,
  резервные каналы (CF/TCP/пул).
- **Интеграция**: логи в бакете «Telegram» просмотрщика логов, карточка
  «Telegram Proxy» в центре обновлений (обновляется с ZPUI), данные в
  отчёте.

## 5a. Профиль и подписка (иконка в шапке, бот, веб-кабинет)

- Вкладка «Пользователь» и вход по паролю убраны (3.0). Аккаунт = Telegram.
- **Иконка профиля в тайтлбаре** с окантовкой-статусом: красная — вход не
  выполнен, оранжевая — сервер недоступен, зелёная — авторизован.
- Клик без входа → модалка «Вход через Telegram»: код (клик = копировать),
  шаги, QR на бота, кнопка «Открыть бота» (tg://), имя бота. Поллинг
  подтверждения 2с; после подтверждения — токен сохранён, тост.
- Клик при входе → поповер: имя профиля, статус подписки (активна/триал/
  истекла + дней), «Выйти».
- Бот: регистрация/повторный вход по коду, статус подписки, устройства
  (список/отвязка), веб-кабинет, напоминания 5/3/1/0 дней.
- Веб-кабинет (`/app/`): вход по одноразовой ссылке из бота; подписка,
  устройства, продление (промокод + галочка условий + Robokassa),
  инструкции, условия обслуживания.

## 5b. Туннель (поповер профиля)

- Доступен при активной подписке. Встроенного VPN-клиента в приложении нет —
  приложение управляет **подпиской туннеля для телефона** (клиент Happ):
  ноды, балансировка и лимиты — на стороне сервера.
- Ссылка/QR подписки устройства — сканировать телефоном; персональный токен,
  кнопка «Перевыпустить» (старый QR гасится).
- Выпуск ссылки для дополнительного телефона (со своим токеном); отключение
  туннеля — своего или другого устройства аккаунта.
- Трафик и лимит тарифа видны рядом с QR.

## 6. DNS (`/dns`)

Управление системным DNS: базовые провайдеры, пресет xbox-dns.ru для консолей
и пользовательские серверы. Локального резолвера нет — в систему прописываются
только обычные IPv4-адреса.

### 6.1. Тумблер и состояние

- Мастер-тумблер «Прописать DNS в систему». Активное состояние = в системе
  реально прописаны наши DNS; внешнее изменение DNS (вручную, другой
  программой) гасит тумблер.
- Если прописанные серверы перестают отвечать, DNS снимается сам — система
  возвращается на прежние адреса, приходит уведомление.

### 6.2. Список серверов

- Строки «провайдер + вкл»: пресет **xbox-dns.ru** (первая строка) и базовые
  провайдеры из каталога.
- **Пользовательские записи**: имя + основной/резервный IPv4; опционально
  DoH-адрес — он регистрируется в системе (netsh doh), и Windows сама
  шифрует запросы к таким серверам, где это поддерживается.
  Добавление/редактирование — в модалке; удаление — с подтверждением.

### 6.3. Текущие системные DNS

- Блок «текущие системные DNS»: что реально прописано на адаптерах сейчас
  — по нему видно, активен ли наш DNS.
- Только IPv4: при применении статический IPv6-DNS адаптера снимается в DHCP.

## 7. Монитор (`/monitor`)

История и графики доступности.

### 7.1. Фильтры периода

- Час / День / Неделя.

### 7.2. Визуализации

- **Линейный график доступности** за выбранный период (ось X — время, ось Y — %).
- **График задержки** (latency) по ресурсам.
- **Таблица ресурсов:** имя, средняя доступность за период, текущий статус, количество сэмплов.
- **Топ проблемных:** ресурсы с наибольшей долей неудач.

### 7.3. Экспорт

- Экспорт истории в CSV (для анализа пользователем).

### 7.4. Настройка пула

- Кнопка «Редактировать ресурсы» → модалка со списком доменов (добавить/удалить).

### 7.5. Проверка YouTube (DNS-уровень)

- Отдельная от общего % доступности проверка: системный резолвер сравнивается
  с DoH, полученные адреса проверяются TLS-рукопожатием.
- При обнаружении DNS-подмены (типично для zapret 1.10.x: стратегиям нечем
  починить отравленный резолв) на дашборде появляется баннер с кнопкой
  **«Включить Xbox DNS»** и приходит Windows-уведомление (один раз за сеанс).
- Результат не влияет на общий % доступности и на автоподбор/AutoSwitch:
  стратегии не чинят DNS.

## 8. Диагностика (`/diagnostics`)

Самопроверка системы и рекомендации.

### 8.1. Список проверок

- Карточный список всех проверок (см. [`Бизнес-логика.md`](./Бизнес-логика.md) §10):
  - статус (зелёный/жёлтый/красный);
  - краткое описание;
  - рекомендация (с кнопкой действия, если применимо).

### 8.2. Действия из диагностики

- «Перезапустить движок».
- «Переустановить zapret».
- «Открыть исключения антивируса» (ссылка на инструкцию).
- «Запустить автоподбор».
- «Сбросить настройки к дефолту».

### 8.3. Логи

- Вкладка «Логи» внутри диагностики.
- Просмотр `logs/*.log` с фильтром по уровню (INFO/WARN/ERROR).
- Кнопка «Копировать» (для отправки в баг-репорт).
- Ошибки, показанные пользователю тостами, пишутся в журнал (категория
  «Приложение», уровень ERROR) — и через него попадают в отчёт и на сервер;
  повторного Windows-уведомления при этом не создаётся.
- Кнопка «Открыть папку логов» (в Explorer).

### 8.4. Диагностический отчёт

- Кнопка «Сформировать отчёт» → выбор назначения **«В файл» / «На сервер»**
  до генерации.
- **В файл:** отчёт сохраняется в выбранное место, модалка показывает путь.
- **На сервер:** отчёт уходит в ZPUI Live напрямую (файл на диске не
  создаётся) и привязывается к устройству — виден в админке.

## 9. Обновления (секция «Обновления» в настройках)

Проверка и применение обновлений ZPUI и запрета (zapret2) — без отдельного окна: модалки обновлений открываются прямо в приложении.

### 9.1. Текущие версии

- Карточки версий в настройках:
  - ZPUI (из `versions.txt` → `-X main.version`).
  - ZAPRET 2 (локально установленная версия движка).
  - Telegram Proxy (обновляется вместе с ZPUI).
  - report (модуль, обновляется из `components/report/` на Яндекс.Диске).

### 9.2. Проверка

- Автоматически **при старте приложения** и далее **примерно раз в час во время
  работы** (если включён тумблер «Проверка обновлений»).
- Zapret (zapret2): источник — сервер управления (зеркало апстрима) и GitHub
  bol-van/zapret2; в режиме «Авто» побеждает свежая версия.
- Результат: «актуальная версия» либо «Доступно обновление vX.Y.Z» + Windows-уведомление.

### 9.3. Применение

- В трее при наличии обновления появляются пункты «Обновление ZPUI — скачать» / «Обновление запрета — скачать».
- Кнопка «Скачать» открывает **модалку с прогрессом, которую нельзя закрыть до завершения загрузки**.
- После скачивания в модалке появляется кнопка **«Установить»**:
  - zapret (zapret2): установка в приложении с прогрессом этапов (движок перезапускается, списки и стратегия сохраняются);
  - ZPUI: приложение закрывается и запускается скачанный пакет — обновление
    накатывается поверх старой версии без мастера (данные и запрет не трогаются).
- «Что нового» — клик по номеру версии открывает release notes.

### 9.4. История обновлений

- Список применённых обновлений (из БД событий, вкладка «Монитор»).

### 9.5. Откат версий запрета (кнопка «Версии»)

- На карточке ZAPRET 2 кнопка **«Версии»** открывает список доступных версий:
  версия, источник (сервер / GitHub), дата, отметка текущей.
- Любую версию можно скачать и установить вручную — инструмент отката
  (например, если новая версия запрета сломала YouTube).
- Установка идёт через стандартный механизм: бэкап списков и стратегии,
  распаковка, восстановление состояния; при сбое — откат на предыдущее.
- Список кэшируется на 5 минут; при недоступности одного из источников
  показываются версии другого.

## 10. Настройки (`/settings`)

Все пользовательские предпочтения.

### 10.1. Общие

- **Язык интерфейса:** русский / английский (мгновенное переключение).
- **Тема:** тёмная / светлая / системная — синхронно во всём окне (включая тайтлбар).
- **Автозапуск с Windows:** тумблер. Управляет **службой ZPUI** — она сама
  создаёт/удаляет задачу Планировщика заданий (`schtasks /SC ONLOGON /TN ZPUI`,
  `--hidden`, уровень прав HIGHEST) — запуск при входе с правами администратора
  **без UAC-запроса**. Если служба не установлена/не отвечает, тумблер работает
  с задачей напрямую (прежняя схема, ничего не ломается).
  - Состояние читается напрямую из задачи/службы (языконезависимо) и **не хранится в config.json** — источник истины система.
  - Запись НЕ видна во вкладке «Автозапуск» Диспетчера задач — только в Планировщике заданий.
  - Прежние схемы (запись в реестре `HKCU\…\Run`, ярлык в автозагрузке) мигрируют и очищаются автоматически.
- **Запуск свёрнутым в трей:** тумблер.
- **Игнорируемые VPN:** список VPN, отмеченных «Пропустить» на стартовом
  экране. Удаление записи возвращает вопрос при следующем запуске.

### 10.2. Движок

- **Автозапуск zapret при старте ZPUI:** тумблер.
- **Поведение при ошибке:** «Молча рестарт» / «Показывать тост» / «Открывать диагностику».
- **Лимит рестартов:** слайдер (1–10 за 60 сек).

### 10.3. AutoSwitch

- **Включить:** тумблер.
- **Порог доступности:** слайдер (0–100%).
- **Cooldown:** селектор (5m / 10m / 30m / 1h).
- **Чувствительность (consecutiveFails):** слайдер (1–5).
- **Пул стратегий:** мультиселект карточек.

### 10.4. Мониторинг

- **Интервал поллинга:** селектор (15s / 30s / 1m / 5m).
- **Пул ресурсов:** редактор списка доменов.
- **Хранение истории:** селектор (7 / 14 / 30 дней).

### 10.5. Уведомления

- Настроек уведомлений нет — **все уведомления всегда включены** (ошибки,
  сбои службы, отсутствующие файлы, обновления, падение доступности,
  DNS-подмена YouTube). Сохранённые ранее «выключенные» флаги игнорируются.

### 10.6. Прокси

- (дублирует `/proxy` настройки, в виде компактного блока).

### 10.7. DNS

### 10.8. Экономный режим

Мастер-тумблер + два ползунка (по умолчанию выключено):

- **Экономный режим (главный тумблер)** — разрешает работу режима. Пока он
  выключен, экономия не активируется ни при каких условиях.
- **Степень экономии** (ползунок, 3 позиции, по умолчанию *Низкая*):
  - *Низкая* — интервалы ×5: трафик 2с→10с, ISP 60с→300с, устройства
    60с→300с, sync-маяк 15с→75с, снапшоты БД 5с→25с; проверка доступности
    раз в 30 минут; опрос статуса интерфейсом 2с→5с; декоративные
    CSS-анимации отключаются.
  - *Средняя* — плюс пауза мониторинга трафика (скорости в нуле) и записей
    снапшотов в БД.
  - *Максимальная* — плюс пауза трекера устройств, определения оператора и
    синхронизации (маяк и приём; пиры уходят offline).
- **Срабатывать при заряде** (ползунок, только на ноутбуках, по умолчанию
  «От АКБ»): «Всегда», «От АКБ» (режим активен всё время работы от батареи)
  или порог 10–50% с шагом 5%. При пороге режим включается, когда заряд
  батареи опускается до него, и выключается сам на зарядке (процент растёт
  выше порога). На ПК без батареи ползунок скрыт, а включение режима
  активирует его сразу.

Индикация: значок батареи в нижней части боковой панели, виден всегда, пока
режим активен (в т.ч. после переоткрытия окна). При Средней/Максимальной
вкладки «Монитор» и «Синхронизация» серые с карточкой «отключена» и кнопкой
перехода в настройки. Всё восстанавливается автоматически при выходе из
режима.

## 10.9. Синхронизация устройств (`/sync`)

Перенос данных между экземплярами ZPUI в локальной сети.

- **Обнаружение**: каждое устройство рассылает UDP-маяки и слушает чужие —
  все запущенные ZPUI в одной ЛВС видят друг друга автоматически.
- **Что синхронизируется**: оператор/провайдер, набор стратегий (с
  результатами автоподбора и доступностью), истории доступности и версий
  компонентов. Учётные данные прокси не передаются.
- **Сопряжение по PIN**: при первой синхронизации на устройстве-источнике
  показывается окно с PIN-кодом, который нужно ввести на приёмнике.
- **Доверенные устройства**: после успешного сопряжения устройство
  помечается доверенным — дальнейшая **авто-синхронизация при запуске**
  происходит без PIN.
- **Вкладка списка**: имя устройства, IP:порт, версия ZPUI и zapret;
  кнопки «Синхронизировать» (вручную) и «Отвязать».
- При включении модуль автоматически добавляет правила брандмауэра Windows
  для портов UDP 47321 (обнаружение) и TCP 47322–47340 (сервер).

## 11. Стартовый экран (StartupScreen, оверлей)

Единый стартовый экран без мастера: 7 фаз идут последовательно, каждая — с
прогресс-баром и статусом (детали фаз — [`Бизнес-логика.md`](./Бизнес-логика.md) §7.1):

1. Подключение к бэкенду.
2. Проверка системных компонентов.
3. Проверка Windows-службы запрета.
4. Скачивание/установка движка zapret2 — выполняется сама, если дистрибутива
   нет (авто-источник: сервер + GitHub, побеждает свежая версия).
5. Установка/ремонт Windows-службы запрета (если нужно).
6. **Умный подбор** стратегии (всегда умный): показывается тот же конвейер
   фаз, что и в модалке подбора («определяем провайдера → … → запускаем
   подбор») и строка провайдера.
7. Готово — переход на основной экран.

- Ошибки отображаются inline, без модальных окон; шаги пишутся во фронтовый
  журнал.
- Если движок не поднялся после запуска — модалка сбоя с рекомендациями
  (HVCI) и кнопкой **«Переустановить запрет»**.

## 12. Трей и уведомления

### 12.1. Иконка трея

- Отображается всегда при запущенном ZPUI.
- Левый клик — показать/скрыть окно.
- Правый клик — контекстное меню.

### 12.2. Контекстное меню

- «Открыть ZPUI».
- Инфо-строки: «Запрет: …», «Прокси: …» (тумблер), «Xbox DNS: …» (тумблер).
- «Обновление ZPUI — скачать» / «Обновление запрета — скачать» (видны только при наличии обновлений).
- «Разделитель».
- «Перезапустить» (проходит через службу ZPUI — срабатывает надёжнее, даже если приложение подвисло).
- «Выход» (корректное завершение, не просто скрытие; служба уведомляется, чтобы восстановление не сработало ложно).

### 12.3. Balloon-уведомления

- Запуск движка.
- AutoSwitch сработал.
- Доступно обновление.
- Критическая ошибка (движник упал и не поднялся).

### 12.4. Поведение кнопки «Закрыть»

- По умолчанию: закрытие окна = сворачивание в трей (приложение продолжает работать).
- Опция в настройках: «При закрытии сворачивать в трей» / «Полностью завершать».

## 14. Доступность и UX-принципы

- **Минимум кликов** для частых действий (старт/стоп — одна кнопка на дашборде).
- **Всегда видимый статус** движка (даже в других вкладках — через бейдж в шапке).
- **Понятные сообщения об ошибках** — без стектрейсов, с рекомендацией.
- **Подтверждения для деструктивных действий** (сброс, удаление списков).
- **Локализация** всех строк (см. [`Дизайн-и-типографика.md`](./Дизайн-и-типографика.md) §7).
- **Тёмная тема по умолчанию** (привычная для целевой аудитории).
- **Поддержка DPI-scaling Windows** (читаемость на HiDPI-экранах).
- **Слой анимаций интерфейса**: плавные переходы между вкладками (сдвиг + лёгкий масштаб), ступенчатое появление секций/карточек, press-feedback всех кнопок и тумблеров, пружинное движение ползунка Switch, анимация индикатора активной вкладки. Длительности ~120–240 мс, easing-токены (`--ease-out`, `--ease-spring`). Уважается системная настройка `prefers-reduced-motion`.
