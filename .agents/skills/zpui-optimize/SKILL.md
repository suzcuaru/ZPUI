# Оптимизация ZPUI

## 0. Сначала локализуй, потом меняй

Определи, где узкое место: бэкенд (CPU/диск/сеть — логи, счётчики, диспетчер задач) или UI (частота поллинга, перерендеры). Не оптимизируй вслепую и не плодите интервалы в разных местах — источник интервалов должен быть один.

## 1. Бэкенд: правило нового фонового цикла

- Интервал — только через `power.Stretch(base)` (в экономном режиме растягивается ×5), выход из тика при `power.Active()`; тяжёлый фон глушится при `power.Paused()`. Пакет `internal/power` — образец: `Set`/`Active`/`Paused`/`Stretch` + нативный `kernel32.GetSystemPowerStatus` через `NewLazyDLL`.
- Нативные Win32 API вместо запуска процессов: каждый spawn процессов — заметный расход батареи.
- Ориентиры интервалов (не сделать хуже): трафик 2с→10с, ISP 60с→300с, устройства 60с→300с, sync-маяк 15с→75с, снапшоты БД 5с→25с, availability в экономном режиме — 30 мин. Новые интервалы согласуй с этой шкалой.
- Deep-пауза (`Paused()`) приостанавливает всё, что не влияет на Запрет/прокси/DNS: записи трафика в БД, трекер устройств, ISP-детект, sync-маяк (пиры уходят offline) — это сознательное поведение, не «чинить».

## 2. UI: поллинг и отзывчивость

- Поллинг — через `usePolling` с существующими интервалами; новый таймер чаще существующих не добавлять. В экономном режиме опрос статуса 2с→5с и приостанавливается при скрытом окне.
- Синхронный биндинг дольше ~5 сек замораживает весь WebView — долгие операции только async (горутина + `EventsEmit` или запуск + `GetXxxResult`, поллинг ~2с, таймаут 120с).
- React: следи за deps в `useCallback`/`useMemo` (лишние перерендеры), тяжёлые списки — виртуализация или пагинация, а не «render всё».

## 3. Данные

- SQLite: частые одиночные записи пакетируй; в экономном режиме частота записей растягивается (снапшоты уже 5с→25с). Ретеншн логов — `CleanOld` (сейчас 30 дней; требование пользователя — 7).
- Трафик: считай сессионные дельты per-interface с guard'ами сбросов счётчиков. Суммировать since-boot счётчики напрямую — двойной счёт.

## 4. Рендер и кэш

- Декоративные CSS-анимации глушатся в экономном режиме — новые анимации должны это уважать (посмотри, как сделано в `web/src/styles/index.css`).
- Старый бандл/серый экран после обновления — кэш WebView2: assetserver должен отдавать no-store.

## 5. Проверка результата

Замеряй до и после (CPU/память в диспетчере, расход батареи, частота записей в БД) — «на глаз» не считается. Затем обязательный прогон: `go vet ./...`, `go test ./...`, `cd web && npm run build`.
