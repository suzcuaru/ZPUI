# Цикл разработки ZPUI

## Шаг 0 — перед правками

1. Прочитай релевантный документ из `Документы/` (не знаешь какой — начни с `Архитектура.md`).
2. Сделай снимок: `echo N | cmd //c backup.bat` (создаст копию проекта `ZPUI (X.Y.Z)` рядом с корнем; `N` — ответ на «открыть папку?»).
3. Сверь объём с запросом пользователя: делай ровно запрошенное, без попутных улучшений.

## Бэкенд (Go)

- Новый эндпоинт = два шага всегда: (1) маршрут в карту `web/src/api.js`, (2) метод `func (a *App)` в `internal/app/` (файл по домену: `app_api_zapret.go`, ...).
- Ответы только через `okResp(data)` / `errResp(msg)` из `internal/app/app_api_types.go`; фронт проверяет поле `error`.
- Логи — `slog`, ошибки — явно (`if err != nil`), без паник.
- Долгие операции (>5 сек синхронно = зависший UI): асинхронный запуск + прогресс через `runtime.EventsEmit` либо паттерн «запустил → `GetXxxResult` с поллингом ~2с из фронта, таймаут 120с».
- Внешние процессы — только `executil.HiddenCmd` (обычный `exec.Command` мерцает консольными окнами).
- В биндингах принимай простые типизированные параметры: `map[string]interface{}` из JS приходит пустым.

## Фронтенд (React)

- Все пользовательские строки — через i18n: `useT()`/`t('...')` в компонентах, `tr()` вне React; ключи в `web/src/locales/{ru,en}.json`. Захардкоженных строк в JSX нет.
- API-вызовы — только `api(method, route, body)` из `web/src/api.js`.
- UI-кирпичики — из `web/src/components/ui/` (`Row`, `Switch`, `Modal`, `Button`, `Card`, ...); стили — токены CSS-переменных, никаких хардкод-цветов и магических чисел.
- Переиспользуемая логика — в `web/src/hooks/` (`usePolling`, `useDebouncedSave`, `useServiceToggle`); сохранение настроек — через `useDebouncedSave`.
- В `useCallback`/`useEffect` держи все используемые props в deps — иначе stale closure («параметр не передаётся» — сначала проверь deps).

## Новая настройка (тумблер) — чек-лист

Поле обязано появиться в **обоих** методах, иначе значение молча «слетает» при следующем чтении:

1. `GetConfig()` — отдать поле фронту.
2. `SetConfig()` — принять и записать (для `notify_*` — отдельный `SetNotifyFlags()`).
3. Ключ в `web/src/locales/{ru,en}.json`, UI-тумблер с `useDebouncedSave`.

## Проверки — после любых правок

```bash
go vet ./...          # обязано пройти
go test ./...         # обязано пройти
cd web && npm run build   # обязано пройти
npm test              # vitest, если менял утилиты/хуки
```

## Финал — сборка

После выполнения задачи: `cmd //c build.bat` (frontend → Wails core → модули → `dist/<версия>/`). Под Git Bash хвост build.bat может упасть безвредно — проверь результат по логу `dist/build-<версия>.log` и содержимому `dist/<версия>/`.

## Нельзя (кратко; полный список — AGENTS.md §7)

- Менять окно 960×640 или включать maximize (`internal/app/window_windows.go`).
- Добавлять телеметрию/аналитику; менять лицензию MIT; менять формат API-ответов.
- Связывать фронт/бэк по HTTP — только Wails bindings через `api.js`.
- Править `versions.json` вручную; коммитить без явного запроса пользователя.
- Бампить версию модуля без реальных изменений в нём.
