# Анализ кодовой базы ZPUI

## 1. Сначала документация

Перед разбором нетривиального вопроса открой релевантный документ из `Документы/`:

- `Концепция.md` — что за продукт, аудитория, ограничения
- `Архитектура.md` — стек, компоненты, потоки данных
- `Бизнес-логика.md` — состояния движка, автоподбор, AutoSwitch, обновления, автозапуск
- `Функции.md` — пользовательские функции и карта UI
- `Дизайн-и-типографика.md` — дизайн-система, токены, i18n
- `Задачи/` — текущие задачи и планы

Если код противоречит документации — сообщи об этом пользователю, а не молча выбирай, чему верить.

## 2. Трассировка фичи: UI → бэкенд

Связь строгая и однонаправленная. Ищи фичу по этой цепочке:

1. **UI:** `web/src/pages/*.jsx`, кирпичики — `web/src/components/ui/`
2. **Вызов:** всегда через `web/src/api.js` — `api('GET', '/api/...')`; в route map (`GET_ROUTES`/`POST_ROUTES`) сразу видно, какой метод бэкенда вызывается
3. **Метод бэкенда:** `internal/app/app_api_*.go` — файлы сгруппированы по доменам (`app_api_zapret.go`, `app_api_proxy.go`, `app_api_updates.go`, `app_api_tgproxy.go`, ...)
4. **Доменная логика:** `internal/<домен>/`
5. **Состояние:** `config.json` через `internal/config` (единственный источник истины настроек) и SQLite через `internal/database` / `internal/logdb`

Прямые вызовы `window.go.app.App.*` из компонентов — нарушение конвенции; если встретил, отметь как баг. Формат ответов: `okResp(data)` → `{"status":"ok",...}`, `errResp(msg)` → `{"error":"..."}` из `internal/app/app_api_types.go`.

## 3. Карта подсистем

| Подсистема | Пакет | Суть |
|---|---|---|
| Движок zapret | `internal/zapret` | дочерний `winws.exe`; состояния stopped/starting/running/error/restarting |
| SOCKS5-прокси | `internal/proxy` | раздача обхода на другие устройства |
| Telegram-прокси | `internal/tgproxy` | MTProto-мост через WSS к Telegram DC |
| Xbox DNS | `internal/xboxdns` | DNS-сервер :53 для домашней сети |
| Мониторинг | `internal/monitor`, `internal/blockcheck` | доступность ресурсов (TCP+TLS+HTTP) |
| Обновления | `internal/updater` | Яндекс.Диск + GitHub; проверки только при запуске |
| Синхронизация | `internal/sync` | UDP discovery + HTTP + PIN между устройствами в ЛВС |
| Экономный режим | `internal/power` | растягивание фоновых интервалов |
| Автозапуск | `internal/autostart` | задача Планировщика заданий; состояние НЕ хранится в config.json |
| Отчёты | `internal/reports`, `cmd/report` | диагностические отчёты |

## 4. Правила анализа

- Отвечай ссылками вида `файл:строка` — они кликабельны.
- Не делай выводов о поведении, не прочитав код: имя файла — предположение, код — факт.
- **Ограничение git:** репозиторий трекает только релизные артефакты (exe, установщики, CHANGELOG, workflow) — `internal/`, `web/src/` и `*.go` в gitignore. Поэтому правки исходников не видны в `git status`, а история коммитов = история релизов. Не ищи историю правок конкретной функции в `git log` — её там нет.
- Версии модулей — `versions.txt` (поля `zpui`, `report`, `tgproxy`). `versions.json` — собираемый артефакт, вручную не правится.
